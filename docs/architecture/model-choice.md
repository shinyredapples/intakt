# Model choice

Routing rules in the configuration pick the tier a build starts on. This page covers the rules and their reader (part 1 of the model-choice task, T60); raising the tier after a failure and recording the choice in the ledger are later parts.

**Facts.** `Core\Build\Contract\BuildFacts` holds the facts of a build: the tier a `model:` label names (`labelledTier`, null without one) and the paths the build touches. `BuildFacts::fromLabels($labels, $paths)` reads a `model:<tier>` label with `Tier::tryFrom`, so a value that names a model or a vendor is ignored, and the last valid label wins. The class has no field for anything the builder says, so a job cannot choose its own model; a test pins its fields.

**Rules.** `Domain\RoutingRules` holds the default tier and the sensitive path globs. `Domain\ModelRouting::choose()` returns a `Contract\TierChoice` (tier and `TierReason`): a touched path matching a sensitive glob gives the strong tier (`sensitive-path`) whatever the label says, as the design's [label rules](../design/05-architecture/04-labels.md) require (safety rules beat labels); else the label's tier (`label`); else the default tier (`default`). Globs are matched by `Review\Contract\PathGlob`, the same matcher the review rules use (see [Capability tiers per project](capability-tiers.md)).

**Configuration.** A project's `build` section (`Infrastructure\BuildRoutingConfiguration`, its own tree because the projects tree of the AI module refuses unknown keys) has `tier` (one of the `Tier` values, default `standard`) and `sensitive_paths` (a list of non-empty UTF-8 globs, default empty); other keys, an unknown tier and a map instead of a list are refused at boot. `config/packages/ai.php` lifts the section out of each project, gives every project the defaults when it has none, and sets the container parameter `BuildServices::ROUTING`. `Infrastructure\ConfiguredBuildRouting` implements `Contract\BuildRouting::tierFor($project, $facts)` over it and throws `BuildRoutingNotConfigured` for an unknown project.

**Door.** `UseCase\ShowBuildTier\ShowBuildTierCommand` (`intakt:build:tier <project> [--label=L ...] [--path=P ...]`) prints `tier <tier>, reason <reason>`, reads only the configuration and calls no model. Nothing in the build loop calls `BuildRouting` yet. Tests: `ModelRoutingTest`, `BuildFactsTest`, `BuildRoutingConfigurationTest`, `ConfiguredBuildRoutingTest`, `ShowBuildTierCommandTest`.
