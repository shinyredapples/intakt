# Pull requests handed to Intakt

While Intakt runs beside the existing loop, Intakt opens its pull requests under its own GitHub App identity and the loop leaves every pull request that identity opened (owner decision 2 of 2026-10-31 in `docs/plan.md`). Plan task T71 (issue #3001, part 1 of #353) makes Intakt recognize those pull requests as handed over to it, so later parts treat them as counted. This part records the recognition only: posting Intakt's review with the round's one-time token, asking the owner for protected heads, and the merge through Intakt alone are planned (parts 2 and 3 of #353). The weekly report on the loop's own heads ([Weekly report](weekly-report.md)) reads nothing of it and is unchanged.

## What counts as handed over

A pull request counts as handed to Intakt when Intakt's own ledger holds a `change_opened` line for it with `opening` `created`: the line `PushBranch` appends after the GitHub App opened the pull request with `POST /pulls`, or after a retry found it open with this App's own bot account as its author ([Branch push](branch-push.md)), with the same `project` and the same `change` (the pull request's address, which is also the change id the listing returns). `ChangeOpening::openOrUpdate()` answers an `OpenedChange` (the `ChangeId` and its `Opening`: `Created` or `Updated`), and `PushRecords::open()` writes the `Opening`'s value as `opening`. It also counts when its `change_opened` lines of the project carry no `opening` at all (written before openings were recorded) and the forge answers that Intakt's App created it (`Plugin/Forge/Contract/ChangeAuthorship::isCreatedByIntakt(ChangeId)`, below). And it counts when it has no `change_opened` line of the project at all (a push that stopped after `POST /pulls` and before its record, also when the branch moved since) and the forge answers the same. The watcher never decides from what a listing reports: title, body, labels and branch are text others can shape. Only GitHub's own `user.login` is read as the author, compared with the App's bot account as GitHub names it (`GET /app`), which no person or other App can take.

`GitHubForge`'s `Infrastructure/GitHubChangeAuthorship` implements `ChangeAuthorship` (the container's only implementation, so its alias): it parses the `ChangeId` with `PullRequestAddress`, reads `GET /repos/{owner}/{repo}/pulls/{n}` through `TrustAnswers::ofInstallation()` with the token of `CheckedInstallationTokens::current()` and answers `true` only when `user.login` is a bot account and `SteeringIdentities::isOwn()` matches it (the slug from `GET /app` with the App's JWT; a person's login asks no `GET /app`). An address that is no GitHub pull request, a refused or unreachable read (a `404` too), an answer without the author's login, a failed token mint, a refused installation check and a failed `GET /app` are `ForgeReadFailed`; a read the installation's rate-limit pause refuses stays `ForgeRateLimited`.

The addresses are compared without letter case, because the push builds the address from the configured `github` value (`owner/name`) and the listing takes GitHub's `html_url`, which spells the owner and repository as GitHub does, and GitHub does not tell them apart by case. A repository renamed after the pull request was opened is not followed: its listed address no longer matches.

Not handed over:

- a pull request with no `change_opened` line of the project, such as one the loop opened, when the forge answers that someone other than this App created it. The forge is asked on each tick while such a pull request is open, because nothing records the answer; a rate limit stops the author reads of that tick (below);
- a pull request whose `change_opened` lines all say `updated`: Intakt's push found an open pull request of the branch that someone else, the loop included, opened, and only updated its text;
- a pull request whose `change_opened` lines all lack `opening` (written before this rule existed) when the forge answers that someone other than this App created it, the loop included. The forge is asked on each tick while such a pull request is open and not recognized, because nothing records the answer; a later push of its branch records an `opening`, after which the forge is no longer asked. A retry of a push whose only record lacks `opening` also asks the forge again, even for the same head and text (`PushRecords::openedChange()` takes no such record as done), so it records `created` or `updated`;
- a `change_opened` line of another project with the same address, because projects are told apart;
- a pull request that someone else opened at a head Intakt's push only intended (a `change_intended` with no `change_opened`): the forge answers another author. When the process stopped after GitHub created the pull request, the next tick asks the forge and recognizes it without another push; a later push also finds it open with this App's bot account as its author, updates it and records `created`. A push whose look-up finds the branch's open pull request without a `user.login` text, or with an empty one, throws `ForgeWriteFailed` before the `PATCH`, so no `updated` is recorded for an author GitHub did not name and the push can be retried. A head that moved after the stopped push (someone pushed to the branch) does not matter: the forge is asked for every open pull request without a `change_opened` line, whatever its head.

## Where it happens

`Core/Watcher/UseCase/WatchPullRequests/ChangesHandedToIntakt::recognizeAmong()` runs in each watch tick ([Forge contract](forge-contract.md), the Scheduler tick), inside `ChangedHeads`' database transaction, after the listing and before the changed pull requests are queued. The transaction runs under the project's listing lock (`FindChangedPullRequests::whileListing()`), which is released only after it committed or rolled back, so an overlapping tick of the same project stops with `ListingInProgress` instead of reading the ledger before this tick's `change_handed_to_intakt` lines are committed and appending them a second time. It is given every open pull request of the project as the last completed listing saw it (`FindChangedPullRequests::openOf()`, the `watcher_seen_change` rows), not only the changed ones, so a pull request listed before its `change_opened` line was written is recognized on the next tick even when the listing is unchanged (HTTP 304). It reads the `change_opened` and `change_handed_to_intakt` lines (`Ledger::readOfKind()`), keeps those of the tick's project (a line that is not valid JSON is skipped), and appends one `change_handed_to_intakt` line (`project`, `change`, `head`: the address and head the listing named) through `WatcherLedger` for each open pull request with no `change_handed_to_intakt` line yet that has a created `change_opened` line, or only `change_opened` lines without `opening`, or no `change_opened` line, and in these last two cases an answer `true` from `ChangeAuthorship`. The forge is not asked for a pull request with a created or updated line. It decides first and appends afterwards: every open pull request is decided, the forge's author reads included, before the first `change_handed_to_intakt` line is appended, because a failure behind an append would roll the transaction back under a line the entity manager still holds. An author the forge cannot read (`ForgeReadFailed`) leaves that pull request unrecognized on this tick, logs a warning (`The author of {change} in {project} could not be read, so it is checked again on the next tick: {reason}`) and goes on with the others; a `ForgeRateLimited` author read does the same and asks no further author on this tick. The listing's record, the other recognitions and the queueing of the changed heads stand, and the next tick asks again, because it is given every open pull request. A line the ledger refuses throws `WatcherEventNotRecorded`, which rolls the transaction back with the listing's record, so the next tick tries again.

The line is a fact, not a state: a second `change_handed_to_intakt` line for the same pull request (two workers both recognizing it) says the same thing, and readers treat the lines as a set.
