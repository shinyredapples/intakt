# Pull requests handed to Intakt

While Intakt runs beside the existing loop, Intakt opens its pull requests under its own GitHub App identity and the loop leaves every pull request that identity opened (owner decision 2 of 2026-10-31 in `docs/plan.md`). Plan task T71 (issue #3001, part 1 of #353) makes Intakt recognize those pull requests as handed over to it, so later parts treat them as counted. This part records the recognition only: posting Intakt's review with the round's one-time token, asking the owner for protected heads, and the merge through Intakt alone are planned (parts 2 and 3 of #353). The weekly report on the loop's own heads ([Weekly report](weekly-report.md)) reads nothing of it and is unchanged.

## What counts as handed over

A pull request counts as handed to Intakt when Intakt's own ledger holds a `change_opened` line for it with `opening` `created`: the line `PushBranch` appends after the GitHub App opened the pull request with `POST /pulls` ([Branch push](branch-push.md)), with the same `project` and the same `change` (the pull request's address, which is also the change id the listing returns). `ChangeOpening::openOrUpdate()` answers an `OpenedChange` (the `ChangeId` and whether this call created the change), and `PushRecords::open()` writes `opening` `created` or `updated` from it. Nothing the forge reports about the pull request decides it: its author, title, body, labels and branch are text others can shape, while the ledger holds only what Intakt's push wrote.

The addresses are compared without letter case, because the push builds the address from the configured `github` value (`owner/name`) and the listing takes GitHub's `html_url`, which spells the owner and repository as GitHub does, and GitHub does not tell them apart by case. A repository renamed after the pull request was opened is not followed: its listed address no longer matches.

Not handed over:

- a pull request with no `change_opened` line, such as one the loop opened;
- a pull request whose `change_opened` lines all say `updated`: Intakt's push found an open pull request of the branch and only updated its text, so someone else, the loop included, may have opened it;
- a `change_opened` line without `opening` (written before this rule existed);
- a `change_opened` line of another project with the same address, because projects are told apart;
- a pull request whose last record is a `change_intended` with no `change_opened` (the forge call failed, the record was refused, or the process stopped in between): the ledger does not know that the pull request exists, so it is not recognized from it. When the process stopped after GitHub created the pull request, the next push finds it open and updates it, so its record says `updated` and it stays unrecognized: a missed pull request, never a loop pull request counted.

## Where it happens

`Core/Watcher/UseCase/WatchPullRequests/ChangesHandedToIntakt::recognizeAmong()` runs in each watch tick ([Forge contract](forge-contract.md), the Scheduler tick), inside `ChangedHeads`' database transaction, after the listing and before the changed pull requests are queued. It is given every open pull request of the project as the last completed listing saw it (`FindChangedPullRequests::openOf()`, the `watcher_seen_change` rows), not only the changed ones, so a pull request listed before its `change_opened` line was written, or already open when this step was deployed, is recognized on the next tick even when the listing is unchanged (HTTP 304). It reads the `change_opened` and `change_handed_to_intakt` lines (`Ledger::readOfKind()`), keeps those of the tick's project (a line that is not valid JSON is skipped), and appends one `change_handed_to_intakt` line (`project`, `change`, `head`: the address and head the listing named) through `WatcherLedger` for each open pull request with a created `change_opened` line and no `change_handed_to_intakt` line yet. A line the ledger refuses throws `WatcherEventNotRecorded`, which rolls the transaction back with the listing's record, so the next tick tries again.

The line is a fact, not a state: a second `change_handed_to_intakt` line for the same pull request (two workers both recognizing it) says the same thing, and readers treat the lines as a set.
