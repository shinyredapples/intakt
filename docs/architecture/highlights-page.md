# The published highlights page

`bin/highlights` assembles the highlights page from `docs/highlights.d/` and it is never committed (the `highlights` row of [Quality gates](quality-gates.md)). `.github/workflows/highlights.yml` publishes it from main. `bin/pages` assembles the same page with a relative link to the journey page beside it, `../journey/` ([The Pages site](journey-page.md#the-pages-site)); the workflow publishes the page `bin/pages` writes. The site opens on a front page, `docs/pages/index.html` with its files in `docs/pages/assets/`, and the highlights page is at `https://shinyredapples.github.io/intakt/highlights/`.

**Decision:** GitHub Pages at `https://shinyredapples.github.io/intakt/`, through GitHub's Pages deployment (no `gh-pages` branch): a stable address, no sign-in, rebuilt from main on a push touching its inputs and once a day, unlike a release or CI artifact.

- Runs on a push to main touching its `paths`, daily and by hand (`gh workflow run highlights.yml`), never for a pull request. Both jobs have the guard `if: github.repository == 'shinyredapples/intakt' && github.ref == 'refs/heads/main'`.
- `build` has a read-only token (`contents`, `pages`, `issues` and `pull-requests`), checks out the full history (fragments are ordered by the first-parent commit that added each, and fragments one merge adds at once by the history of the parents it merged, see the `highlights` row of [Quality gates](quality-gates.md)), records the journey's API answers and the issue states with `bin/journey-record` on the runner, runs `bin/pages` on them in the CI image as uid 1000, rewrites both written pages (`highlights/index.md` and `journey/index.md`) with each `{{` and `{%` written as a Liquid string that prints it (`{{ "{{" }}`, `{{ "{%" }}`, with `sed`), renders with `actions/jekyll-build-pages` and uploads with `actions/upload-pages-artifact`.
- `publish` runs no checkout and no repository code: its one step, `actions/deploy-pages`, deploys that artifact to the `github-pages` environment. Only it holds the `pages` write permission and the `id-token` permission.
- `bin/pages` settles feature-row statuses on the published page only: for each row of a feature table (four cells, Feature, What, Status, Where) written done or in progress, it reads the local `#n` references of the Where cell (`symfony/ai#2875` is not one, but a bare `#n` after it or in the text of a link to another repository is, so feature rows name upstream work in the `owner/repo#n` form only) in `issue-states.json` of the `--recorded` folder (`IssueStates`; `bin/journey-record` derives the file with `jq` from the recorded issues, which also list pull requests, merged ones as closed) and `HighlightStatuses` writes in progress when one is open, else done when all are closed. Rows written planned, rows naming no issue, rows naming a number the file lacks with none open, and the Found in the beta table keep their written status. With a missing, unreadable, empty or invalid `issue-states.json` (no usable state, or no `--recorded`) nothing is settled and the journey page is still built, since it reads only `issues.json`, and the page omits the one-sentence rule that otherwise follows the journey link. `bin/highlights` and the `highlights` gate stay offline, so `docs/highlights.md` still matches its assembly.
- A failed run leaves the previous page. Runs are serialized (`concurrency` group `highlights`).

The owner sets the repository's Pages source to "GitHub Actions" once; until then `publish` fails. `tests/Gates/HighlightsWorkflowTest.php` pins the triggers, permissions, guard and `publish` job; that the recording step comes before the page step, and that the recording step's own `env:` sets `GH_TOKEN` to the job's token while the job and the workflow set none (other steps' `env:` is not checked for `GH_TOKEN`), with no secret read by any step; and that the page step passes `--recorded=/workspace/_journey-api`. It runs the step's escape command on stand-in copies of both pages to check the escaped openings, the unchanged rest and that a failed escape fails the step.

**Decision:** the page source escapes Liquid instead of turning it off. `actions/jekyll-build-pages` builds with the `github-pages` gem, which pins Jekyll 3.10 and Liquid 4.0.4; Jekyll 3.10 ignores `render_with_liquid: false` (a Jekyll 4 key) and runs Liquid on any page that holds `{{` or `{%`. Liquid prints each escaped string back before Markdown runs, so the published page shows a fragment's `{{` or `{%` as the fragment wrote it, and nothing restricts what fragments may contain. The front page needs no escape: it has no front matter, so Jekyll copies it and its assets unchanged, and `PagesCommandTest` checks that it holds no `{{` or `{%`. `README.md` (Documentation), `docs/guide/symfony-in-intakt.md` and the preamble in `docs/highlights.d/layout.md`, which the page itself carries, link to that address.
