# Prompt assembly and its gate

How text reaches a model, and which `bin/check` rule keeps it that way (#2518, #2520; the threat model's [third-party text](../design/05-architecture/14-threat-model.md#third-party-text)).

- **Untrusted text only fenced (D1).** Untrusted text enters a prompt only as `Review/Contract/FencedText`, rendered inside a fence whose boundary the text cannot forge; Intakt's own instructions, leads and notices are typed `literal-string`, so the `phpstan` gate refuses a runtime string there.
- **One assembly class (D2).** `Review/Contract/PromptAssembly` is the one class that creates Symfony AI messages (`system()`, `systemWithRole()`, `user()`, `notice()`, and the strings of `userText()`, `document()` and `toolAnswer()`); its methods are listed under Prompt assembly in [Reviewer agent](reviewer-agent.md). The one exception: a reviewer role's `prompt` from the owner's panel configuration enters the system message verbatim, only through `systemWithRole(instructions, ReviewerConversation)`, which reads it from the conversation, never from a plain string.
- **The gate (D3).** `config/gates/src/PhpStan/RawPromptMessageRule.php`, registered in `config/gates/phpstan.neon` with the class names it guards, reports `intakt.rawPromptMessage` for `Message::ofUser()`, `Message::forSystem()`, `Message::ofAssistant()`, `new UserMessage` and `new SystemMessage` anywhere under `src/` or `bin/` outside `PromptAssembly`. It resolves the class through the scope, so an import alias, a class name held in a variable and a first-class callable (`Message::ofUser(...)`, which PHPStan hands over as a `StaticMethodCallableNode`, so `RawPromptCallableRule`, registered beside it, passes the call it stands for to `RawPromptMessageRule`) are refused alike, and a factory name only known at runtime counts as a factory. Tests are not judged: they build stored conversations as fixtures and never send them to a provider.
- **The role prompt's one source.** For the exception to hold, the same rule reports `intakt.unprovenRolePrompt` for a `new ReviewerConversation` in `ReviewWithReviewerHandler` unless `rolePromptIsProven()`: no argument is unpacked, and the role prompt argument (the first positional one, or the one named `rolePrompt`) is a `rolePrompt()` call on a value PHPStan types as `RoundReviewer` (`readsTheRoundReviewersRolePrompt()`). A nullsafe call, a `rolePrompt()` of another type and any other string fail. Constructing a `ReviewerConversation` elsewhere is not judged by this rule.

Tests: `tests/Gates/RawPromptMessageRuleTest.php` and `tests/Gates/RawPromptCallableRuleTest.php`, with fixtures under `tests/Gates/Fixtures/raw-prompt-*`.
