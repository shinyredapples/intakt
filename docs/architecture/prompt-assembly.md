# Prompt assembly

Every message Intakt sends to a model is put together by one class, `Intakt\Core\Review\Contract\PromptAssembly`, so no runtime string reaches a prompt unfenced ([threat model](../design/05-architecture/14-threat-model.md#third-party-text), #2518, #2811).

- **Types (D1):** the assembly takes Intakt's own text (instructions, leads, notices) only as `literal-string`, so the `phpstan` gate refuses a runtime string there, and untrusted text only as a `FencedText` from `Fence::wrap()` or `PromptCut::fenced()`. Its methods are listed under Prompt assembly in [Reviewer agent](reviewer-agent.md) and [Builder prompt](builder-prompt.md).
- **One assembly class (D2):** `PromptAssembly` is the only class of Intakt's own code that creates a Symfony AI message (the agent component still adds the model's own assistant and tool messages). The one exception (maintainer decision of 2026-11-18, from #2518): a reviewer role's configured prompt (the `prompt` of a panel member in the owner's panel configuration) enters the system message verbatim, only through `PromptAssembly::systemWithRole()`, which takes it from a `ReviewerConversation`, never as a plain string.
- **The gate (D3):** `RawPromptMessageRule` (`config/gates/src/PhpStan/RawPromptMessageRule.php`, identifier `intakt.rawPromptMessage`) refuses `Message::ofUser()`, `Message::forSystem()` and `Message::ofAssistant()` (also called as a first-class callable, through an object of `Message` or a class name PHPStan knows, and with the method name as a string PHPStan knows, such as `Message::{'ofUser'}()` or `Message::$method()` after `$method = 'forSystem'`) and `new UserMessage(...)` and `new SystemMessage(...)` (also `new $class(...)` with a class name PHPStan knows). A class name PHPStan knows is a constant string such as `Message::class` or a value typed `class-string<SystemMessage>`; a plain `string` or a method name built at run time names nothing and is not judged. The rule refuses these anywhere but inside `PromptAssembly`. PHPStan hands a first-class callable such as `Message::ofUser(...)` to rules as a node of its own, so `RawPromptMessageCallableRule` passes the call it stands for to the same rule. The finding names the call and says to build the message through `PromptAssembly`, with Intakt's own text as a literal and untrusted text as a `FencedText`.
- **The role prompt (identifier `intakt.unprovenRolePrompt`):** in `ReviewWithReviewerHandler`, the one place that starts a reviewer's conversation from the panel, the same rule accepts `new ReviewerConversation(...)` only when its role prompt (the first positional argument, or the one named `rolePrompt`) is a `rolePrompt()` call on a `RoundReviewer`; a literal, any other string, a nullsafe call, another conversation's `rolePrompt` and any unpacked argument (`...$arguments`, which names no role prompt, also when it follows the role prompt) are refused. In `SymfonyAiVendor`, whose retries start a new conversation for the stopped reviewer, the same identifier accepts a role prompt only when it is the `rolePrompt` property of an existing `ReviewerConversation` (`$stopped->rolePrompt`); a string, a round reviewer's `rolePrompt()`, a nullsafe fetch and any unpacked argument are refused there.
- **Where the role prompt's carriers are built (#2812):** because the type alone cannot prove where a role prompt came from, the same rule limits where the objects that carry one are constructed (the checks are in `config/gates/src/PhpStan/RolePromptCarriers.php`, class names resolved by `ClassNames`). `new ReviewerRole(...)` is accepted only in `ConfiguredPanels` (the owner's panel configuration) and `SampleProject` (fixed literal roles), and `new RoundReviewer(...)` only in `ReviewRound` (identifier `intakt.reviewerRole` for both); `new ReviewerConversation(...)` only in `ReviewWithReviewerHandler` and `SymfonyAiVendor` (identifier `intakt.reviewerConversation`). The class is resolved as for the message classes (an alias, `new (ReviewerRole::class)(...)`, a class-name string PHPStan knows, any letter case), and every class a class-string union names is judged, so an allowed carrier cannot hide a refused one. A class string typed with an interface or parent class of a carrier (such as `class-string<HasPlace>`, which `RoundReviewer` implements) counts as naming that carrier (`ClassNames::standingFor()`), in a class and in a trait alike; every part of an intersection bound counts, an object shape too: the bound names the carrier unless its whole type rules the carrier out, so neither `class-string<HasPlace&Countable>` nor `class-string<HasPlace&object{label: string}>` names `RoundReviewer`, which does not implement `Countable` and has no `label` property. A bound PHPStan cannot decide counts as naming the carrier, so an unusual bound (a shape, a callable or a conditional type) may be refused although it names no carrier: a known limit. The place is judged by the exact class name. A trait body counts as outside every class, also when an allowed class uses the trait: the rule judges a carrier the trait names literally (a class name, `X::class` or a class-name string literal) where the trait is declared, so a trait no class uses is covered too (PHPStan enters a trait body only through a class that uses it). An anonymous class in a trait (`new class () {}`) builds no carrier and passes, whether a class uses the trait or not. Any other `new` in a trait (`new self`, `new static`, `new $class`) is judged inside each class that uses the trait, directly or through another trait, with the method's types: it is refused under the identifier of the carrier its type names (`intakt.reviewerConversation` for `class-string<ReviewerConversation>`), and as `intakt.reviewerRole` when a part of its type names no class (a plain `string`, `object` or `mixed`); a type that names only other classes, such as `$wrapped ? ArrayObject::class : stdClass::class`, passes. In a trait no analyzed class uses, such a `new` has no method types and is refused where the trait is declared by `UnusedTraitCarrierRule` (except a `new self`, `new static` or `new parent`, or the same with `self::class`, `static::class` or `parent::class`, inside an anonymous class in the trait, which names that anonymous class or the parent it names literally, never a carrier, since carriers are final), from what `RunTimeTraitConstructionCollector` and `UsedTraitCollector` collect; a run of changed files only skips that last check, since it misses the classes that use a trait. Outside traits, a class named only at run time (`new $class()` with a plain `string`), reflection and denormalization are not judged, as for the message classes. `PromptAssembly` may build messages but none of these objects. `PanelReviewer` and `ReviewerRole` are `final readonly`, so these sites are where a role prompt comes from; the chain of trust ends there: the panel configuration's input is the owner's, and a `RoundReviewer` loaded from storage was built by `ReviewRound`. Each finding names the classes that may build the object.
- **Scope:** the gate judges `src/`, `bin/` and `config/`; a message built under `tests/` is not judged.
- **Literal callables and traits:** an array literal with exactly the keys `0` and `1` (implicit or explicit, in any written order) whose value at `0` names `Message` and whose value at `1` is a factory name, or a value only known at run time that may be a string (typed `string`, `?string` or `mixed`), is refused (`[Message::class, 'ofUser']`, `[1 => 'ofUser', 0 => Message::class]`), and so is the callable string `'Symfony\AI\Platform\Message\Message::ofUser'`. An array with any other key (`['class' => Message::class, 'method' => 'ofUser']`) is not a callable and passes. A class string may start with at most one backslash, as in PHP, so a form with two is not a callable and passes. A trait's own file decides whether its code is judged, so a trait under `src/` is judged even when only a class under `tests/` uses it.
- **Not judged:** computed callables (`array_reverse([...])`, `ReflectionMethod::invoke()`, any function result) are never judged.

Tests: `tests/Gates/RawPromptMessageRuleTest.php`, `tests/Gates/RawPromptMessageCallableRuleTest.php` and `tests/Gates/UnusedTraitCarrierRuleTest.php`.
