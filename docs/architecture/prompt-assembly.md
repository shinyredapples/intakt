# Prompt assembly

Every message Intakt sends to a model is put together by one class, `Intakt\Core\Review\Contract\PromptAssembly`, so no runtime string reaches a prompt unfenced ([threat model](../design/05-architecture/14-threat-model.md#third-party-text), #2518, #2811).

- **Types (D1):** the assembly takes Intakt's own text (instructions, leads, notices) only as `literal-string`, so the `phpstan` gate refuses a runtime string there, and untrusted text only as a `FencedText` from `Fence::wrap()` or `PromptCut::fenced()`. Its methods are listed under Prompt assembly in [Reviewer agent](reviewer-agent.md) and [Builder prompt](builder-prompt.md).
- **One assembly class (D2):** `PromptAssembly` is the only class of Intakt's own code that creates a Symfony AI message (the agent component still adds the model's own assistant and tool messages). The one exception (maintainer decision of 2026-11-18, from #2518): a reviewer role's configured prompt (the `prompt` of a panel member in the owner's panel configuration) enters the system message verbatim, only through `PromptAssembly::systemWithRole()`, which takes it from a `ReviewerConversation`, never as a plain string.
- **The gate (D3):** `RawPromptMessageRule` (`config/gates/src/PhpStan/RawPromptMessageRule.php`, identifier `intakt.rawPromptMessage`) refuses `Message::ofUser()`, `Message::forSystem()` and `Message::ofAssistant()` (also called as a first-class callable, through an object of `Message` or a class-name string) and `new UserMessage(...)` and `new SystemMessage(...)` (also `new $class(...)` with a class-name string) anywhere but inside `PromptAssembly`. PHPStan hands a first-class callable such as `Message::ofUser(...)` to rules as a node of its own, so `RawPromptMessageCallableRule` passes the call it stands for to the same rule. The finding names the call and says to build the message through `PromptAssembly`, with Intakt's own text as a literal and untrusted text as a `FencedText`.
- **The role prompt (identifier `intakt.unprovenRolePrompt`):** in `ReviewWithReviewerHandler`, the one place that starts a reviewer's conversation from the panel, the same rule accepts `new ReviewerConversation(...)` only when its role prompt (the first positional argument, or the one named `rolePrompt`) is a `rolePrompt()` call on a `RoundReviewer`; a literal, any other string, a nullsafe call, another conversation's `rolePrompt` and unpacked arguments (`...$arguments`, which name no role prompt) are refused. Constructing `ReviewerConversation` elsewhere (such as the vendor's retry, which carries the stopped reviewer's prompt forward) is not judged by this rule.
- **Scope:** the gate judges `src/`, `bin/` and `config/`; a message built under `tests/` is not judged.
- **Not judged:** literal callable arrays and strings (`[Message::class, 'ofUser']`) and the file a trait's code is written in wait for part 2 of #2811; computed callables (`array_reverse([...])`, `ReflectionMethod::invoke()`, any function result) are never judged.

Tests: `tests/Gates/RawPromptMessageRuleTest.php` and `tests/Gates/RawPromptMessageCallableRuleTest.php`.
