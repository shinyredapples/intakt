# Provider failure cases

Plan task T25 runs review rounds on purpose where providers fail and records how each one ends. Each case is a scripted run through the real vendor stack (`AccountLimitedVendor`, `SymfonyAiVendor`, `TierPlatform`, `AccountFailoverPlatform` with the account cooldowns, `UsageLedger` on the Doctrine ledger) down to Symfony AI's `MockPlatformFactory` platforms and the test platform `FailingWhenRead`, so no case reaches a provider. The outcome is read through `ReviewChange`, the use case behind `intakt:review`, so the decision and the reasons are the ones the console prints. The library probes of T25 are listed in [Upstream reproductions](upstream-reproductions.md).

**Shared fixture.** `tests/Core/Review/UseCase/RunReviewRound/ScriptedRound.php` builds the stack for the project `alpha` with the standard tier on Anthropic and OpenAI as its substitute, one account each, three parallel calls allowed per provider, and cooldowns on real time. Its workers take the queued reviewer messages in turn and queue a message again at once after a recoverable failure, as Messenger's retry does once the delay has passed; a round that needs more than 30 deliveries fails the test. `InFlightTogether` (same folder) runs the next queued delivery after a call is sent and before its answer is read, so several reviewers' calls are in flight together by construction, with no timing. `usagePhasesByCall()` lists the `usage_recorded` phases of each vendor call.

| Case | Outcome | Recorded reason | Test |
|---|---|---|---|
| Shared rate limit: the three reviewers of a round send their calls together, Anthropic answers each with a 429 (reset 300 s), then OpenAI does the same | `blocked`; each provider cools down once (one `account_cooled_down` per provider for three limited calls); the reviewers move to the substitute (`ReviewerMovesToAnotherAccount`), then end `blocked` with `NoProviderLeft`; each of the six interrupted calls has a `started` and one `unsettled` row, none `settled`, and all three calls of the first pass were started before the first limit was read | `role-N reviewer failed, Every provider of the tier is out: anthropic for N s, openai for N s.` per reviewer, and the same reason, without the role, in each `reviewer_blocked` event | `tests/Core/Review/UseCase/RunReviewRound/SharedRateLimitTest.php` |
| Shared rate limit beside an answer: the first reviewer's call answers `changes` while the other two calls are in flight, those two are limited together on both providers | `changes`; the answered call is `settled` once, the four interrupted calls are `unsettled` once each | the same reason for `role-2` and `role-3` | `SharedRateLimitTest.php` |

A tier without substitutes does not end on a rate limit: its reviewers wait together for the account's reset (`ReviewerRateLimited` with the reset as the retry delay, see [Review rounds](review-rounds.md)) and are reviewed then, as the design asks (`docs/design/05-architecture/06-budget-and-model-planner.md`, cooldowns per quota account); `RateLimitedReviewerTest.php` and `SameVendorAccountFailoverTest.php` cover that wait.
