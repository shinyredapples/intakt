# Provider failure cases

Plan task T25 runs review rounds on purpose where providers fail and records how each one ends. Each case is a scripted run through the real vendor stack (`AccountLimitedVendor`, `SymfonyAiVendor`, `TierPlatform`, `AccountFailoverPlatform` with the account cooldowns, `UsageLedger` on the Doctrine ledger) down to Symfony AI's `MockPlatformFactory` platforms and the test platform `FailingWhenRead`, so no case reaches a provider. The outcome is read through `ReviewChange`, the use case behind `intakt:review`, so the decision and the reasons are the ones the console prints. The library probes of T25 are listed in [Upstream reproductions](upstream-reproductions.md).

**Shared fixture.** `tests/Core/Review/UseCase/RunReviewRound/ScriptedRound.php` builds the stack for the project `alpha` with the standard tier on Anthropic and OpenAI as its substitute, one account each, three parallel calls allowed per provider, and cooldowns on real time. Its judge is a `VerdictPerRole` (same folder), which `ReviewChange` also asks whether each tier is mapped, because the stack maps only the standard tier. Its workers take the queued reviewer messages in turn and queue a message again at once after a recoverable failure, as Messenger's retry does once the delay has passed; a round that needs more than 30 deliveries fails the test. `InFlightTogether` (same folder) runs the next queued delivery after a call is sent and before its answer is read, so several reviewers' calls are in flight together by construction, with no timing. `askingForTools()` is a platform that asks for one more tool round on every call, so a long conversation needs no waiting. `usagePhasesByCall()` lists the `usage_recorded` phases of each vendor call.

| Case | Outcome | Recorded reason | Test |
|---|---|---|---|
| Shared rate limit: the three reviewers of a round send their calls together, Anthropic answers each with a 429 (reset 300 s), then OpenAI does the same | `blocked`; each provider cools down once (one `account_cooled_down` per provider for three limited calls); the reviewers move to the substitute (`ReviewerMovesToAnotherAccount`), then end `blocked` with `NoProviderLeft`; each of the six interrupted calls has a `started` and one `unsettled` row, none `settled`, and all three calls of the first pass were started before the first limit was read | `role-N reviewer blocked, Every provider of the tier is out: anthropic for N s, openai for N s.` per reviewer, and the same reason, without the role, in each `reviewer_blocked` event | `tests/Core/Review/UseCase/RunReviewRound/SharedRateLimitTest.php` |
| Shared rate limit beside an answer: the first reviewer's call answers `changes` while the other two calls are in flight, those two are limited together on both providers | `changes`; the answered call is `settled` once, the four interrupted calls are `unsettled` once each | the same reason for `role-2` and `role-3` | `SharedRateLimitTest.php` |
| Quota exhausted during a round, no reset given (`RateLimitExceededException` without a retry delay, the structured signal Symfony AI has for a quota): the first reviewer's call answers `changes`, every later call on Anthropic and on OpenAI is refused | `changes`; each provider cools down once, whatever the number of refused calls; the answered call is `settled` once, each interrupted call has a `started` and one `unsettled` row, none `settled` | `role-2 reviewer blocked, Every provider of the tier is out: anthropic for N s, openai for N s.` (and `role-3`) | `tests/Core/Review/UseCase/RunReviewRound/QuotaExhaustedMidRoundTest.php` |
| Quota exhausted from the first call on both providers, no reset given | `blocked`, with the same reason for each reviewer in the round and in its `reviewer_blocked` event | `role-N reviewer blocked, Every provider of the tier is out: anthropic for N s, openai for N s.` | `QuotaExhaustedMidRoundTest.php` |
| Long run, the reviewer asks for tools on every call until `ReviewerRuns::MAX_ROUNDS` (30) is reached, on the first call and on its retry | `blocked`, no verdict; each of the two calls is `settled` once | `role-1 reviewer failed, the reviewer's answer could not be read as a verdict: the reviewer was still asking for tools after 30 rounds of tool calls.` | `tests/Core/Review/UseCase/RunReviewRound/LongRunTest.php` |
| Long run, a rate limit without reset arrives after five tool rounds on Anthropic and on OpenAI | `blocked`; each call is `started` and `unsettled` once, none `settled` | `role-1 reviewer blocked, Every provider of the tier is out: anthropic for N s, openai for N s.`, the same reason without the role in its `reviewer_blocked` event | `LongRunTest.php` |
| Long run that answers after five tool rounds (control) | the verdict's own decision (`approve`); the call is `settled` once | none | `LongRunTest.php` |

A tier without substitutes does not end on a rate limit: its reviewers wait together for the account's reset (`ReviewerRateLimited` with the reset as the retry delay, see [Review rounds](review-rounds.md)) and are reviewed then, as the design asks (`docs/design/05-architecture/06-budget-and-model-planner.md`, cooldowns per quota account); `RateLimitedReviewerTest.php` and `SameVendorAccountFailoverTest.php` cover that wait.
