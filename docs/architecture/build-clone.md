# Build clone

A build works in a fresh clone of the project made from its [bare mirror](mirror.md), never from the remote. The clone holds main and the task's branch and no other ref: no other branch, no tag, no remote and no remote-tracking ref, and no commit only another branch reaches. The one exception is a task's verified source: a `Source: <branch>@<sha>` line from a trusted author adds that one commit (and the commits it reaches) as `refs/source/<branch>`.

`php bin/console intakt:build:clone <project> <branch> <directory> [--task=<file>] [--trusted-author]` (`MakeBuildCloneCommand`) calls the use case. `--task` names a file holding the task's text, which is read for a source line; without it the clone has no source. With `--trusted-author` the source line is honored. Without it a task that holds a source line gets one line `comment <text>` (the text is `MakeBuildCloneCommand::SOURCE_IGNORED`, saying the line is ignored because its author has no write access), however many source lines it holds, and the clone is made without a source. On success it prints `clone <directory>` and exits with 0; on a `ReportableFailure` (such as `BuildCloneNotMade`, `BranchNameRefused`, `ProjectNameRefused`, `SourceLineNotUnique` or `RepositoryAttributesRefused`) or Symfony's `IOException` (a task file that cannot be read, a missing file or a folder for example) it prints the message in an error block and exits with 1, and no clone is made. Any other exception (an `InvalidArgumentException`, for example, which marks a programming error) is left to the console, which prints it and exits with 1 as well.

`SourceLine::in($text)` in `src/Core/Git/Domain/` reads the source line: a line of its own, `Source: <branch>@<sha>` with a full commit id in lowercase hex (40 characters, or 64 for SHA-256), optionally followed by spaces or tabs and a Windows line ending. Anything else is prose and not a source line: a sentence that mentions one, a quoted, indented or code line, a line inside a fenced code block, a short or uppercase commit id, `source:` in lowercase. A fence follows Markdown: a line of three or more backticks (with no backtick after them) or tildes, indented by at most three spaces, opens it, and a line of only the same character, at least as many, closes it; a fence that is never closed runs to the end of the text. A line inside an `<!-- external -->` ... `<!-- /external -->` block is prose as well, because the threat model counts copied text as untrusted even in a trusted task: a line holding only `<!-- external -->` (spaces or tabs around it allowed) opens the block, a line holding only `<!-- /external -->` closes it, and a block that is never closed runs to the end of the text. The markers are read before the fence state: a fence inside an external block changes nothing, a block opened inside a fenced code example still hides what follows it, and the closing marker ends only the external block, never a fence. A text with two source lines is refused with `SourceLineNotUnique`, because picking one would decide for the author. `SourceLine::isNamedIn($text)` tells whether a text holds one or more, for the comment.

`MakeBuildClone::make($project, TaskBranch $branch, $directory)` in `src/Core/Git/UseCase/MakeBuildClone/` makes it; `TaskBranch` (in `src/Core/Git/Domain/`) holds the branch name and the source line, if any:

1. The mirror is `var/mirrors/<project>.git` (`Intakt\Core\Git\Domain\Mirrors`, the one home of the project-name rule that `UpdateMirror` uses too). A project whose mirror has no `HEAD` file has no mirror yet, and the clone is refused.
2. Main is the branch the mirror's `HEAD` names (`git --git-dir=<mirror> symbolic-ref --quiet HEAD`), because the mirror's `HEAD` follows the remote's default branch. A mirror whose `HEAD` is detached, or names a ref outside `refs/heads/` (a tag, for example), has no main, and the clone is refused.
3. The branch must pass `git check-ref-format --branch <branch>`, and git's answer must be the name itself, because git expands a name such as `@{-1}` to another branch. A branch that is main itself is refused.
4. A source is verified in the mirror before anything is made: its branch must pass the same branch rule (an unsafe branch is a `BranchNameRefused`), the mirror must hold that branch (`show-ref --verify --quiet refs/heads/<branch>`), and the commit must be on it (`merge-base --is-ancestor <sha> refs/heads/<branch>`, which also fails for a commit the mirror does not hold), and the id must name a commit itself (`cat-file -t <sha>` answers `commit`), because `merge-base` peels an annotated tag to its commit and the fetch would then put the tag object at the source ref. Otherwise the clone is refused.
5. The mirror's object format is read (`rev-parse --show-object-format`), because a fetch from a SHA-256 mirror into a SHA-1 repository fails.
6. The [disk floors](disk-floors.md) are checked with `DiskSpace::holdAt(<folder>)`, where `<folder>` is the parent of `<directory>` or, while that does not exist yet, the nearest folder above it that does (`NearestFolder::of()`), before any folder is made, because on a disk out of inodes `mkdir` itself fails. Below a floor the clone is refused with `BuildCloneNotMade` and the reason from `DiskHold::reason()` (`the disk of <folder> holds new work: <free> free bytes, below the floor of <minimum>`, or `inodes`), with a `NewWorkHeld` carrying the hold as its cause, and a disk that cannot be read (`FreeSpaceUnreadable`) is refused the same way with its message, so no folder is made. An inode read that times out (Symfony Process's `ProcessTimedOutException`) is refused the same way with fixed words, `The free space of <folder> cannot be read: df timed out after 10 seconds.`, and without the timeout as its cause.
7. The folder is reserved: its parent folders are made, and the clone is refused when anything (a folder, a file or a link, even a dangling one) is already at the path (`is_link() || file_exists()`, because a thread-safe PHP, the build CI and the image use, follows a link inside `mkdir` and would create a dangling link's target). Then the folder itself is made with a single `mkdir`, which fails when a folder or a file is at the path by then (a dangling link that appears between the check and the `mkdir` is still followed on a thread-safe PHP). A clone therefore never mixes with what a folder already holds, and of two calls for the same folder only the one whose `mkdir` succeeds goes on; the other is refused with `the folder already exists`.
8. `git init --initial-branch=<branch> --object-format=<format>` makes the clone in that folder, with the mirror's object format.
9. `git fetch --quiet --no-tags --no-write-fetch-head --update-head-ok -- <mirror> +refs/heads/<main>:refs/heads/<main>` fetches main. Init and fetch replace `git clone`, because a clone would add a remote, remote-tracking refs and tags. `--update-head-ok` lets the fetch write the task's branch, which is the branch `HEAD` names.
10. When the mirror holds the task's branch (`show-ref --verify --quiet refs/heads/<branch>`), it is fetched the same way; otherwise the branch starts at main (`update-ref`).
11. A verified source is fetched the same way by its commit id, `+<sha>:refs/source/<branch>`, so the ref is at the verified commit only and the clone holds no later commit of that branch. The ref is read-only for the build in the sense that it is not a branch: a commit in the clone moves the checked-out task's branch, never `refs/source/<branch>`.
12. `git checkout --force --quiet` fills the work tree from the task's branch. It writes no `ORIG_HEAD`.

Every call is built by `HardenedGit`. The calls in the mirror come from `callInBareRepository()` (`--git-dir=<mirror> --bare`, no work tree), as in `UpdateMirror`; `init` names the clone's own git folder (`--git-dir=.git`), because git refuses the pinned work tree without one, and records no `core.worktree` for it. The fetches allow the `file` transport only (`GIT_ALLOW_PROTOCOL=file`), because git reads a local path as that transport. The fetches are local, so they are not retried ([Retried network git calls](network-git.md) are for the remote).

A step that fails throws `BuildCloneNotMade` with git's message (or, for a source, the reason in Intakt's words), except that parent folders that cannot be made (a file in the way, for example) throw Symfony's `IOException`. When the folder was already reserved by this call, it is removed, so a clone that failed half-way is never taken for a build clone. A project name that is not a safe folder name throws `ProjectNameRefused` (from `Mirrors::pathOf()`), and a branch or source branch that is unsafe, or a branch that is main, throws `BranchNameRefused`; both are `ReportableFailure`s.

The [build job](build-job.md) (`intakt:build:run`) takes a build clone made here as its input. Two callers make one. The console command: the person who runs it says whether the task's author has write access (`--trusted-author`), and the comment for an ignored source line is printed, not posted on the issue. And [`intakt:build:task`](build-task.md), whose `GitBuildCheckout` calls the use case with the branch only, so its clone never has a source.
