## The demo with docker compose

Plan task T23, part 2. `compose.yaml` builds the image from the `Dockerfile` and runs it as the service `intakt` with the env file `.env.local` (required; `.env.dist` is its template: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `HF_TOKEN`, `APP_SECRET`, `MERCURE_JWT_SECRET`, and the optional `MCP_OWNER_TOKEN`, all empty; `.dockerignore` keeps `.env.local` out of the image), the volume `intakt-data` at `/app/var/data`, the port `127.0.0.1:7781:7781`, `INTAKT_CONFIG=/app/var/data/intakt.yaml`, `INTAKT_SAMPLE_REPOSITORY=/app/var/data/sample-repository` and `INTAKT_COMPOSE_SERVICE=intakt` (the service's own name; `.env` sets it empty for every other install; `ComposeDemoTest` requires it on every service in `compose.yaml`, so a second service added later has to set it too).

On every start, before the migrations, `docker/entrypoint.sh` hands a non-empty `HF_TOKEN` to the `openai_compatible` provider: when neither `OPENAI_COMPATIBLE_BASE_URL` nor `OPENAI_COMPATIBLE_API_KEY` is set in the environment, it exports `OPENAI_COMPATIBLE_BASE_URL=https://router.huggingface.co` (the Hugging Face router; without `/v1`, because the generic bridge appends `/v1/chat/completions`) and `OPENAI_COMPATIBLE_API_KEY` with the token's value. An endpoint the owner set in the environment wins and the token is not used. Either way `HF_TOKEN` is one of the held credentials redacted from the log ([conventions](conventions.md)).

When `INTAKT_SAMPLE_REPOSITORY` is set, `docker/entrypoint.sh` requires `INTAKT_CONFIG` and, after the migrations, exports the owner's MCP settings (below), rebuilds the container (removes `var/cache/$APP_ENV`, then `cache:warmup` in a new process, because the image's container was compiled at build time without keys or projects, and `cache:clear` kept it after the seed), runs `intakt:sample:seed "$INTAKT_SAMPLE_REPOSITORY" "$INTAKT_CONFIG"` and rebuilds the container again. A failed seed stops the entrypoint before the server starts. Without the variable nothing of this runs. The dashboard's first-run page reads the same variable as the repository of the sample change it offers to review (First-review step in [Dashboard](dashboard.md)).

The `image` job of `.github/workflows/ci.yml` ([CI](ci.md)) runs `docker/verify-first-start.sh intakt:ci` on the image it built for the smoke test: the image on an empty volume with a placeholder key, then, once the admin API answers, `intakt:review:panel sample` in the running container. No model is called. It is a smoke check, because a stale container did not fail every start; `EntrypointSampleSeedTest` plants one before and after the seed and requires both removed.

`Core/Review/UseCase/SeedSampleProject/SeedSampleProjectCommand` (`intakt:sample:seed <repository> <configuration>`) holds the lock `review-sample-seed` (waited for) while it seeds, each part only when it does not exist yet:

- **The project:** `SampleProject` asks the Ai module's `Contract\EnabledAccounts` which of Anthropic, OpenAI and `openai_compatible` (in that order; the providers one key enables) have an enabled account; `openai_compatible` counts only when `OPENAI_COMPATIBLE_BASE_URL` is exactly `SampleProject::HUGGING_FACE_ROUTER` (`https://router.huggingface.co`), because its seeded models are router models another endpoint would not know. With none it prints `Set ANTHROPIC_API_KEY or OPENAI_API_KEY or HF_TOKEN to seed the sample project.` (names from `Provider::variables()`, with `HF_TOKEN` for `openai_compatible`) and exits 1. Otherwise it maps the tiers `strong` and `light` to the first keyed provider and `standard` to the last (one key: all three on it; two or three keys: `standard` on the last of them), each with a fixed model (`claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5`; `gpt-5`, `gpt-5-mini`, `gpt-5-nano`; `moonshotai/Kimi-K3:deepinfra` for every router tier, except `standard` when `strong` is on the router too, which gets `openai/gpt-oss-120b:novita`, so a panel on the token alone still has models of two makers). The file also gets a top-level `budget.price_date` and a `budget.prices` block with the list price of each of those models it names (see [Round cost](round-cost.md)), so the first review's cost is a figure. The router models name their router provider after the colon, because the router's default provider may refuse tools together with structured output (Groq and Cerebras did; DeepInfra, Baseten and Novita accepted both). It builds the panel as Review's `Contract\Panel` (quorum `all`; `correctness` on `strong`, `security` on `standard`, budget 10 each, each on the provider its tier maps to) and writes project `sample` with `tiers` and `review` as YAML to the configuration file, which `config/packages/ai.php` then reads and validates like any project file. An existing file is kept as it is, whatever it holds.
- **The repository:** `SampleRepository` builds what `fixtures/sample-repository/README.md` describes (`main` from `base/`, `sample-change` adding `pull-request/`, `main` checked out) with `Core/Git/Contract/HardenedGit` calls (`init` without the pinned work tree, which git refuses there), a fixed author, committer and date (`2026-11-01T00:00:00+00:00`), so every install builds the same commits. It builds in a sibling `<repository>.partial-<random>` directory and renames it into place, so an interrupted build leaves nothing a later start would keep. An existing directory is kept untouched.

The owner's MCP token is made by `docker/entrypoint.sh`, not by the command: in the demo branch (`INTAKT_SAMPLE_REPOSITORY` set) it exports `MCP_OWNER_ACCESS` (default `mcp_tool_write`, so a client can start a review) and `MCP_OWNER_TOKEN`. A token from `.env.local` wins; otherwise `mcp-owner-token` beside `INTAKT_CONFIG` on the data volume is read, or made first: a draft from `mktemp` (mode 0600) gets 32 random bytes as hex (`od`, `tr`) and is hard-linked into place with `ln`, which fails when another start linked first, so starts at once on one volume all read the same complete token. The token is assigned before it is exported, so a failed write is not hidden; anything but 64 hex characters (the folder missing or read-only, the name taken by a folder) stops the start before the seed with `intakt: could not make or read the MCP owner token in <file>; set MCP_OWNER_TOKEN or make its folder writable`. The exports come before the first container rebuild, so the seed, the web process and the workers see them, and the token does not change on a restart.

The seed prints no review command. In the demo branch, once the web server and the workers are started, the entrypoint's one-second poll (the one that restarts ended consumers) also asks, until both answer, the health check's URL (`http://${CADDY_ADMIN:-localhost:2019}/metrics`) and then the dashboard (`http://localhost:$DASHBOARD_PORT/`) with `curl --fail --max-time 2`. On the first poll where both answer it runs `intakt:sample:show "$INTAKT_SAMPLE_REPOSITORY"` once and never asks again; a failed run prints `intakt: could not print the review command; ...` to standard error and the start goes on. Asking from the poll instead of waiting before it keeps crashed consumers restarting and the TERM trap working while the server comes up. A start without `INTAKT_SAMPLE_REPOSITORY` never asks.

`Core/Review/UseCase/ShowSampleReview/ShowSampleReviewCommand` (`intakt:sample:show <repository>`), its own use case beside the seed's, reads the seed's `SampleProject` and `SampleRepository` constants and prints one block between two lines of `=`: `Open the dashboard: http://localhost:<DASHBOARD_PORT>`, then the `intakt:review` command line for `sample-change` with the project, the repository, the base and the task `SampleProject::TASK`, as `php bin/console intakt:review ...`, preceded by `docker compose exec <service> ` when `INTAKT_COMPOSE_SERVICE` is not empty, so the compose demo's reader runs it from the host shell in the repository folder, then, when `MCP_OWNER_TOKEN` is not empty, the `claude mcp add` line for `<REVIEW_MCP_BASE_URL>/mcp/owner` with the token as a bearer header (the image sets `REVIEW_MCP_BASE_URL` to `http://localhost:7781`). Each line is printed whole, never wrapped, so it copies as one command. Being the last thing the entrypoint prints, the block ends the start's output: the consumers start with `--quiet`, so no consumer banner follows it (see `container-image.md`); request logs the server writes later can still follow it.
