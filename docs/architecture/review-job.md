# Review job

Plan task T58, the review job's script (#1923, part 2 of #1861; design: [overview](../design/05-architecture/01-overview.md), [reviews](../design/05-architecture/07-reviews.md)). A review job will run one reviewer in a [job container](job-containers.md) built from [the review job image](job-images.md#the-review-job-image), against a read-only checkout of the exact head, reaching only its vendor through the job's proxy ([Egress](job-containers.md#egress)). This part is the job's command alone, `docker/job/review.sh`: nothing starts it yet. The job classes that mount the checkout, pass the prompt, set the allowlist and read the answer, the runner that picks review jobs over the in-process reviewer, and the review's output and schema come with later parts.

## In the container

`docker/job/review.sh <checkout> <head> <prompt file> <provider> <model>` (POSIX `sh`, with `env`, `sed`, `grep`, `find`, `git` and `claude` or `codex`) runs as the job's command after the [start check](job-containers.md#start-check). It writes `review.log` (each refusal as `refused: <reason>`, git's and the CLI's errors, then `<provider> exited with <status>`) and `answer` (the CLI's standard output as it wrote it) into `INTAKT_JOB_OUTPUT`. Any refusal exits with 1 before the CLI runs, and leaves no `answer`; otherwise the script exits with 0 whatever the CLI's status, so the CLI can never end the job with the code of a refused checkout. Five arguments are needed (`refused: usage: ...` otherwise).

1. **Environment.** Every exported `GIT_*` variable is unset before the first git call (the image may set `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_CONFIG_COUNT` and the like), and so is `NODE_OPTIONS`, which would load code into the CLI. Only `GIT_CONFIG_GLOBAL=/dev/null` and `GIT_CONFIG_NOSYSTEM=1` are set, so git reads no global or system settings.
2. **Proxy only.** `NO_PROXY`, `no_proxy`, `ALL_PROXY` and `all_proxy` are unset, so no request of the CLI bypasses the proxy. `HTTPS_PROXY` must be set, and `https_proxy`, `HTTP_PROXY` and `http_proxy` must equal it (`the job has no egress proxy`); `INTAKT_JOB_EGRESS` must not be empty (`the job has no egress allowlist`); and a job in its reduced mode is refused (`the start check failed: <INTAKT_REDUCED_MODE>`). The job's internal network has no way out but its proxy, which lets through only the allowlist.
3. **Provider and prompt.** `claude_code` or `codex`; any other value is `no reviewer CLI for the provider <provider>`. The prompt file must be a readable regular file (`the prompt cannot be read`).
4. **Read-only.** `<checkout>/.git` must be a folder, not a link (`the checkout has no .git folder of its own`), and no file or folder in the checkout, its `.git` included, may be writable for the job's user (`the checkout is writable`), as on a read-only mount: `find <checkout> -exec` tests each entry with `[ -w ]`, which follows a link to its target, and an entry `find` cannot read refuses the checkout too. A writable file stays writable inside a read-only folder, so checking the two folders alone is not enough.
5. **Clone settings only.** `.git/commondir`, `.git/config.worktree`, `.git/objects/info/alternates` and `.git/info/attributes` are refused (`the checkout has .git/<file>`); `git clone` writes none of them, and attributes such as `ident` would let a changed file compare equal to the head. And `.git/config` must be a regular file. `git config --file .git/config --list` may hold only what `git clone` or `git init` writes on Linux: `core.repositoryformatversion` 0 or 1, `core.filemode=true`, `core.bare=false`, `core.logallrefupdates=true`, `extensions.objectformat` `sha1` or `sha256`, `remote.origin.url`, `remote.origin.fetch`, `branch.<name>.remote` and `branch.<name>.merge`; any other setting or value (an fsmonitor, a hooks path, a filter, an include, `core.filemode=false`) is `the checkout has a setting a clone does not write`, and git never runs it. A non-empty `.git/info/exclude` is not refused, because `git clone` writes one with comment lines.
6. **Exact head.** `<head>` must be a full commit id (40 or 64 lowercase hex digits, `the head is not a commit id`), and `rev-parse --verify --quiet HEAD^{commit}` of the checkout must print it (`the checkout is not at <head>`).
7. **No change.** Every git call on the checkout is pinned to it (`checkout_git`: `git --git-dir=<checkout>/.git --work-tree=<checkout> --no-replace-objects --no-optional-locks -c core.untrackedCache=false`), so a replace ref (`refs/replace/<head>`) cannot make git compare the checkout against another commit's tree, and nothing is written into the checkout. Its index is not trusted either, because flags such as `skip-worktree` or crafted file times could hide a change: `read-tree HEAD` writes a fresh index to `$TMPDIR/review-index`, which every check below uses (through `GIT_INDEX_FILE` on those calls only) and which is removed afterwards.
   - `status --porcelain --untracked-files=no --ignore-submodules=none` must print nothing: a changed, deleted or added tracked file is `the checkout differs from the head`. It runs with `--attr-source=<empty tree>` (the id `hash-object -t tree --stdin` gives for the repository's object format), so the head's `.gitattributes` cannot normalize a change away either (`ident` hiding text inside `$Id: ... $`, `eol` hiding carriage returns). In turn a head whose attributes rewrite content on checkout (`ident` with a `$Id$` keyword, `eol=crlf`, `working-tree-encoding`) is refused even when unchanged; `text` with `eol=lf` on Linux is not, as it writes the content unchanged.
   - `ls-files --others --exclude-per-directory=.gitignore` must print nothing (`the checkout has untracked files`). It reads only the `.gitignore` files in the checkout, never `.git/info/exclude` or a global excludes file, so `*` in `info/exclude` hides nothing; a file the head's `.gitignore` ignores, such as `vendor/`, is allowed.
   - A `.gitignore` the head does not hold could ignore itself and what it hides, so `ls-files --others --ignored --directory --exclude-per-directory=.gitignore` must list no `.gitignore` (`the checkout has a .gitignore the head does not hold`). An ignored folder such as `vendor/` is listed as one entry, so a package's own `.gitignore` in it is allowed.
8. **The CLI** runs in the checkout (entered in a subshell whose input, output and error files are opened first, so relative paths keep naming the same files) with the prompt file on its standard input:
   - `claude_code`: `claude -p --model <model> --output-format json --tools Read,Grep,Glob --allowedTools Read,Grep,Glob --setting-sources '' --strict-mcp-config --no-session-persistence`, with `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`: only file reads, and no user, project or local settings and no MCP server.
   - `codex`: `codex exec --json --sandbox read-only --ephemeral --ignore-user-config --ignore-rules --disable <feature>... --model <model> --config web_search="disabled" -`, the same features switched off as for the in-process Codex reviewer (`IsolatedCodexCli`): `shell_tool`, `unified_exec`, `apps`, `plugins`, `browser_use`, `in_app_browser`, `computer_use`, `multi_agent`, `image_generation`, `view_image` and `hooks`.

`HOME` and `TMPDIR` are the job's own tmpfs work area.

## Open

These are decided by the runner's issue (part 2 of #1650), not here: how a `codex` reviewer reads the checkout while its shell tools are off; whether `--setting-sources ''` keeps a `CLAUDE.md` or `.claude/` folder of the head out of Claude Code's prompt; how far Claude Code's `Read` tool reaches outside the checkout; and the statement that the review image is built from main's tree, not from the head under review.

## Tests

`tests/Core/Review/ReviewScriptTest.php` runs the real `docker/job/review.sh` with `sh -c` on a temporary clone made read-only by removing every write permission bit (skipped for the superuser, who ignores them), with scripted `claude` and `codex` on the path. It covers the CLI's arguments, folder, input and answer for each provider (the Codex features compared with `IsolatedCodexCli`'s list), each refusal above with the CLI not running, a writable tracked file and a writable folder inside a read-only checkout, `* ident` in `info/attributes`, a changed `$Id: ... $` under the head's own `* ident` and carriage returns under its own `eol=lf` (an unchanged checkout under `eol=lf` allowed, one under `* ident` refused), a replace ref for the head pointing at a commit whose tree matches a changed checkout, `*` in `info/exclude` with a planted untracked file, a planted self-ignoring `.gitignore`, a `skip-worktree` flag hiding a change, an fsmonitor whose command never runs, exported git variables that do not reach git, and the CLI's environment without `GIT_*` variables (but the two settings), `NODE_OPTIONS` or a proxy bypass. No review job has run against a live engine yet.
