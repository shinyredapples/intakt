## Server status

Plan task T34, part 1 (the reading side), part 2 (#619, the dashboard row) and part 3 (#620, the container health check). `src/Core/Server/` reads FrankenPHP's admin API from inside the container:

- `Contract/ServerStatus::read()` (`#[NoDiscard]`) returns a `Contract/ServerReading` with three fields, each either its value or `Contract/EndpointDown` (a `reason`): `threads` (`WorkerThreads`: `busy` and `idle`), `metrics` (`ServerMetrics`: `queueDepth` and `workerRestarts`) and `hub` (`HubHealth`: `healthy` or `unhealthy`). One source that is down never hides the others.
- `Infrastructure/AdminApi` takes `FRANKENPHP_ADMIN_URL` (default `http://localhost:2019` in `.env`) as a `Uri\Rfc3986\Uri` and refuses, before any request, a URL that is not plain `http` on `localhost`, `127.0.0.1` or `[::1]`, or that carries credentials (`Contract/AdminApiNotOnLocalhost`, a `ReportableFailure`). It sends `GET` to the URL's scheme, host and port plus the path, dropping any query or fragment in `FRANKENPHP_ADMIN_URL` (no admin endpoint reads one, and a credential there would reach the server's request log), with no redirects, a 2-second timeout and a 2-second limit; a transport failure is `EndpointDown` with the reason `<path> did not answer`, never the transport's message, because that quotes the request URL and the board shows the reason.
- `Infrastructure/AdminApiServerStatus` reads three paths. `/frankenphp/threads`: only threads whose `Name` starts with `Worker PHP Thread` count; `busy` counts `IsBusy`, `idle` counts the others whose `State` is `ready` (a booting or restarting thread counts as neither). `/metrics` (FrankenPHP's Prometheus text, through `Infrastructure/PrometheusSamples`): the queue depth is `frankenphp_queue_depth` plus every `frankenphp_worker_queue_depth` series, the restarts are the sum of the `frankenphp_worker_restarts` series, and an absent labeled series counts as zero, because FrankenPHP leaves it out until it first counts. `/mercure/health/ready` (the hub's `mercure_health` admin module): `200` with `{"status":"ok"}` is healthy, `503` or another `status` is unhealthy.
- Any other HTTP status, a threads answer without a list of threads with string `Name` and `State` and boolean `IsBusy`, metrics with a sample line that does not parse, without `frankenphp_queue_depth`, or with `NaN` or an infinity in a series the reader counts (the format allows them, so they are accepted in any other series) or a counted total that, rounded, falls outside the PHP `int` range, and a hub answer without a string `status` are `EndpointDown` with the path and the reason, never a default value.
- Door: `php bin/console intakt:server:status` (`UseCase/ShowServerStatus/ShowServerStatusCommand`) prints the four values, or `down (<reason>)` for each, and exits non-zero when a source is down or the URL is refused. The board's infrastructure row is the second reader (see [Dashboard](dashboard.md), "Infrastructure row").
- Checks (#3864, part 1 of #3826, decision D1): the health checks have one home in `Contract/`, so the board, `intakt:server:health` and `intakt:doctor` judge a reading the same way and no check has a second implementation.
- `Contract/InfrastructureCheck` is one check's result: `passes()`, `problem` and `fix` (both null when it passes), and `presented()`, which hands a caller either what the check read or the reason its source could not be read.
- `Contract/HubVerdict::of()` is the hub check: `hub down (<reason>)` for `EndpointDown` (fix: check that FrankenPHP runs with the Caddyfile's `mercure` block and that `FRANKENPHP_ADMIN_URL` points at its admin API), `the hub reports unhealthy` (fix: check the FrankenPHP log for the Mercure hub's error, for example a transport file under `MERCURE_BOLT_PATH` it cannot write), or a pass.
- `Contract/InfrastructureChecks::of()` runs the `threads`, `metrics` and `hub` checks on a `ServerReading` and lists the failing ones' `problems` in that order. Threads: `worker threads down (<reason>)` (fix: check that FrankenPHP is running and that `FRANKENPHP_ADMIN_URL` points at its admin API), or `no worker thread is ready` when `busy + idle` is 0 (fix: check the FrankenPHP log for a worker that fails to boot or keeps restarting); a busy thread counts as ready. Metrics: `server metrics down (<reason>)` (fix: check that the Caddyfile's global options turn on `metrics` and that `FRANKENPHP_ADMIN_URL` points at the admin API). `intakt:doctor` prints the fix texts (see [Doctor](doctor.md)).
- The checks read nothing themselves and so cannot hang: each admin API call behind the reading has the 2-second limit above, and a source that cannot be read is `EndpointDown`, which fails its check. Tests: `InfrastructureCheckTest`, `InfrastructureChecksTest` (one test per check, passing and failing with its fix) and `HubVerdictTest`.
- Health: `php bin/console intakt:server:health` (`UseCase/CheckServerHealth/CheckServerHealthCommand`) is the third reader; the image's health check runs it (see [Container image](container-image.md)). It prints one `unhealthy: <reason>` line per problem of `Contract/InfrastructureChecks` and exits non-zero, or prints `healthy` and exits zero. A refused `FRANKENPHP_ADMIN_URL` prints `unhealthy: <message>` and exits non-zero. The figures need the Caddyfile's global `metrics` option, without which FrankenPHP's `/metrics` has no `frankenphp_queue_depth` and the metrics source reads as unusable.
- Tests: `tests/Core/Server/` replays answers recorded from FrankenPHP 1.13.1 with the Mercure hub (`Fixtures/`, the worker path replaced by `/app`) through `MockHttpClient`, including a down admin API, error statuses and unusable shapes; `threads_no_ready_worker.json` and `threads_all_busy.json` are the recorded threads answer with the worker threads' `State` and `IsBusy` changed, for `CheckServerHealthCommandTest`.
