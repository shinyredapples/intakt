# Parity for the takeover

Only behaviors the switch needs ([plan](../plan.md), M6 to M8). Each line: the requirement, then the test of the build loop that developed Intakt that shows it today (file, and a test name where one states it). Before takeover each line gets the Intakt test that shows the same behavior (T73). Intakt task in brackets.

A done line (`- [x]`, also `- [X]`) names its Intakt tests after `Intakt:`, each as `` `SomeTest::testName` ``; a bare `` `testName` `` belongs to the class named last before it on that line, and other backticked words (a command, a class that is no test) are no test names, unless one of their words ends in `Test` or starts with `test`: such a token is read as a test name, so the gate named `tests` goes without backticks there. A done line stays on one line: only a blank line, a list item or a heading (one to six `#`, then whitespace or the line end) may follow it. `tests/Application/Parity/ParityRecordTest.php` fails when a done line names no Intakt test; has a malformed or near-miss name (such as `SomeTest.testName`), a backtick that is never closed, or a next line that continues it; names a class that no `*Test.php` file under `tests/` declares (outside `Fixtures/` folders), that two files share, or that is abstract or no PHPUnit `TestCase`; or names a method that class lacks or does not declare public. Whether a named test passes is shown by the suite that runs it. In every section every line is judged, open or done: each list item there starts with `- [ ]` or `- [x]` (a `*`, `+` or numbered item, or one without a checkbox, is reported); an open line says after `Intakt:` what is not built yet in one of two forms, `not built yet (<what>, T<n>)` or `not built yet: <what>, T<n>` (either at the start, with no `)` after it, or in a remark in parentheses, right after its `(` or after a `; ` in it, closed by one `)`; text before the marker may hold parentheses, nested to any depth, as long as each one closes, such as a link target `(parity(test).md)`; the `<what>` holds no parenthesis, the task may be `T<n> and T<m>`, and the marker, with that `)`, ends the line), names any Intakt tests that show the part already built (each checked as on a done line), and stays on one line too. The gate lists each such line by its section, line number and first sentence with its tasks; the test pins that list, so a line that turns open or done changes it, and runs one case per line, named by it, that checks each of its tasks is a task of the [plan](../plan.md), so a run that lists its cases (such as `--testdox`) names each behavior not built yet. The `tests` gate of `bin/check` prints nothing for a green run, so there those names show only when a case fails. The judged sections are the list `ParityRecord::JUDGED_SECTIONS`, and the test fails when a `##` heading of this record is not exactly that list, in its order, so a new or renamed section cannot go unjudged. A test planned but not written yet, such as the watchdog's, is named before `Intakt:`, so the gate does not read it and the line stays open until it exists.
