# Status read model

The status is one JSON document per install that reports, per project, the review lane, the watcher's guard decisions, the changes waiting for the owner, the Needs-you items and the last outcomes, plus the install-wide holds and the message queues. The owner's dashboard reads it until Intakt's own dashboard replaces it (plan T68). The read model, its schema and the `intakt:status --format=json` command are built; the local endpoint is the next part of T68.

- **Schema:** `docs/user/status.schema.json` (JSON Schema draft-07). `StatusReadModelTest` validates every document it builds against it with `justinrainbow/json-schema`, and checks that the schema's enums for `holds`, a step's `progress` and an outcome's `decision` list exactly the cases of `Budget/Contract/SharedHold`, `Dashboard/Domain/ReviewerProgress` and `Review/Contract/Decision` (plus `null`).
- **Entry:** `Dashboard/UseCase/ShowStatus/StatusReadModel::json()` encodes `generated_at` (the `ClockInterface` moment, `DATE_ATOM`), `holds` (`Budget/Contract/Holds::sharedInEffect()`, by value, in the order they win; never an end, because an end can be a vendor's reset time, see [Measured use](measured-use.md)), `queues` and `projects` with `json_encode()` (`JSON_THROW_ON_ERROR`).
- **No bus:** nothing is dispatched; every part reads the database or the transport's own store, so a stopped `messenger:consume` still yields a status.
- **Queues:** `Dashboard/Infrastructure/MessageQueues` gets every Messenger transport through `#[AutowireIterator('messenger.receiver', indexAttribute: 'alias')]`, so the list follows `config/packages/messenger.yaml` (`async`, `failed`), and reports `getMessageCount()` for a transport that implements `MessageCountAwareInterface` (the Doctrine transport) and `null` for any other (the `in-memory://` transport of the test environment).
- **Projects:** `Dashboard/UseCase/ShowStatus/ProjectStatuses` builds each section grouped by project and joins them per name; the names are the watcher's projects (`WatcherServices::PROJECTS`) and every project a section names, as strings, sorted with `SORT_STRING`, so a watched project without events is listed with empty sections. It reads the ledger once (`readInOrder()`) and hands that one snapshot to every section (`LedgerReviewPages::boardOf()`, `LedgerFailingHeads::in()`, `LedgerWaitingHeads::in()`), so a watcher line written while the status is read cannot show one head both waiting and failed.
  - `lanes.review`: the board's cards in In review, newest first; each latest round with its change, round id, number, start, `reviewers` (the panel size from `review_started`) and one step per reviewer the ledger has a row for (role, tier, `ReviewerProgress` value). A reviewer's free-text failure or block reason is left out.
  - `guard_decisions`: `Dashboard/Infrastructure/LedgerWaitingHeads` keeps the latest watcher line per project and pull request (nested keys), as `LedgerFailingHeads` does, and reports `pending` for `head_pending` and `red` for `head_red` with `read_again_at` parsed as `DATE_ATOM` (a malformed moment reads as `null`); a later `round_queued`, `head_forgotten` or failure line ends it. `LedgerFailingHeads` adds each failing head that is not handed over as `failed`, with its cause, failures and `retry_at` as `read_again_at`.
  - `waiting_for_owner`: the board's Waiting on you cards (change and latest round id); nothing places a card there yet, so it is empty.
  - `needs_you`: the handed-over heads of `LedgerFailingHeads` (change, cause, failures).
  - `last_outcomes`: the `lastJudgedRound()` of every board card, newest judgment first, at most `ProjectStatuses::LAST_OUTCOMES` (10) per project, with the round's `outcome` (`null` without a recorded quorum, as on the review page) and `judgedAt`.
- **Command:** `Dashboard/UseCase/ShowStatus/ShowStatusCommand` (`intakt:status`, an invokable command) writes `StatusReadModel::json()` as one line with `OutputInterface::OUTPUT_RAW`, so text in a cause or a change name that looks like console markup is printed as recorded. `--format` is the backed enum `StatusFormat` (only `json`, the default), resolved by the Console's `#[Option]` enum support, which refuses any other value with `InvalidOptionException` before the command runs. It exits with `Command::SUCCESS`.
- **No secrets:** every failure cause goes through `Platform/Contract/Redactor` (the held credentials and the secret shapes, like a log line); round ids, change names, roles and tiers are Intakt's own values.

Tests: `tests/Core/Dashboard/UseCase/ShowStatus/StatusReadModelTest.php` (a ledger in memory, a stubbed `Holds`, `Redactor` and transports, a `MockClock`; a forced order in which the watcher records a failed head pending between two reads of the ledger, reported once); `tests/Core/Dashboard/UseCase/ShowStatus/ShowStatusCommandTest.php` (the command through the kernel on SQLite: its output validates against the schema, also with a message queued and no consumer, `json` is the default and `yaml` is refused).
