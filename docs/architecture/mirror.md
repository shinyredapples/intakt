# Bare mirror

Intakt keeps one bare mirror per project at `var/mirrors/<project>.git` (the container parameter `intakt.git.mirrors_directory`, `Intakt\Core\Git\Contract\GitServices::MIRRORS_DIRECTORY`). The mirror is a cache of the remote: if it is lost, the next update clones it again.

## Updating a mirror

`php bin/console intakt:mirror:update <project> <remote>` (`UpdateMirror` in `src/Core/Git/UseCase/UpdateMirror/`) keeps the mirror up to date in place with `git --git-dir=<mirror> fetch --prune --quiet -- <remote> +refs/*:refs/*`, then points the mirror's `HEAD` at what `git ls-remote --symref -- <remote> HEAD` advertises: the branch it names (`symbolic-ref`), or, when the remote's `HEAD` is detached and names no branch, the commit it advertises (`update-ref --no-deref`, a detached `HEAD`, as `git clone --mirror` leaves it). Before that `update-ref`, `git --git-dir=<mirror> fetch --quiet -- <remote> HEAD` fetches the advertised commit by name, because a detached `HEAD` may sit on a commit no branch or tag reaches, which the refs fetch leaves out; only a detached `HEAD` is fetched this way, since an empty remote advertises no `HEAD` and `fetch -- <remote> HEAD` fails there. The remote is named on every call, so a mirror never depends on a remote setting, and the mirror's config names no remote. `--git-dir` pins every call to the mirror, so git never looks upward into the install's own checkout.

- A mirror exists when the path holds `HEAD`, `objects/` and `refs/` and `git rev-parse --is-bare-repository` says `true`. It is fetched in place, so a branch the remote deleted disappears and a bare repository left without refs is filled.
- Anything else (no folder, an empty folder, a folder that is not a bare repository) gets a new mirror: `git clone --mirror --quiet -- <remote> <staging>` into a staging folder `var/mirrors/.<project>.git.<random>`, then renamed to `<project>.git`. The clone takes the remote's object format, so the mirror of a SHA-256 repository is a SHA-256 repository too (`git init --bare` would always make SHA-1, and a fetch from a SHA-256 remote into it fails). Each attempt of the clone gets a new, empty staging folder (`NetworkGit::runEachAttempt()`), so a retry never clones into what a killed attempt left. The clone saves the remote's address as `remote.origin.url` in the staging repository's `config`, and with it any credential in the URL, so `git config --remove-section remote.origin` drops that section before the staging folder is published: the mirror keeps no address and no credential, and a rotated token leaves nothing behind. Every staging folder is removed at the end, so an incomplete mirror is never published.
- The rename runs under the Symfony lock `git-mirror-<project>`, which checks the path again first: when another update published the mirror meanwhile, that mirror is kept, the staging folder is dropped, and the overtaken update then fetches into the published mirror once more (outside the lock, like every fetch), because the update that won may have fetched earlier and the mirror must be at least as fresh as the overtaken fetch. The fetches run outside the lock; git's own ref locks guard them.

A local git step that fails (`config --remove-section`, `symbolic-ref`, `update-ref`) or a rename that fails throws `MirrorNotUpdated`; the console command prints it and exits with 1.

The project name becomes a folder name, so a name must start with a letter or a digit, hold only letters, digits, `.`, `_` and `-`, and not contain `..`. Anything else is refused before git runs. The remote is passed after `--`, so it can never be read as an option. The remote is an argument because a project has no remote setting yet.

All calls are built by `HardenedGit`; `UpdateMirror` unsets `GIT_WORK_TREE` for them because the mirror is bare. The network calls (`clone --mirror`, `fetch` of the refs, `fetch` of a detached `HEAD`, `ls-remote`) run through `NetworkGit`. `HardenedGit` allows no transport protocol and pins a work tree, so `NetworkGit` overrides just three variables for its call: `GIT_ALLOW_PROTOCOL=file:https`, no `GIT_WORK_TREE`, and `GIT_TERMINAL_PROMPT=0` (git never asks for a password). `HardenedGit` itself is unchanged. The retries are described in [Retried network git calls](network-git.md).

The `clone --mirror` call alone carries no `--attr-source` and unsets `GIT_ATTR_SOURCE`. It runs in the mirrors folder, so `HardenedGit` would name SHA-1's empty tree as the attribute source, and a `file://` remote hands that on to its `upload-pack`, which refuses it in a SHA-256 repository (a plain path starts no `upload-pack`, which hides the problem). A bare mirror clone checks out nothing and reads no attributes, and `core.attributesFile=/dev/null` and `GIT_ATTR_NOSYSTEM` still apply. The fetches and `ls-remote` keep the full call, because they run inside the mirror, whose object format is the remote's.
