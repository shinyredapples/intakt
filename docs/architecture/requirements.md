# Requirements and external commands

## In short

Intakt and its checks call programs outside PHP, such as `git`, `composer`, `gitleaks` and the `claude` and `codex` CLIs. This page lists each one, who calls it, what for, and whether you need it. To run Intakt you need only Docker or Podman, because the container image ships the rest. To work on Intakt and run `bin/check`, you need more tools on your machine, and `bin/check` names any that are missing before it runs a gate.

Worth knowing:

- The full `bin/check` needs Linux tools such as `unshare` and `setsid`; on another system, run it on a Linux machine or virtual machine (the [development setup](development-setup.md)'s container has no Composer, so it is not one).
- Calls through Symfony Process use an argument list, never a shell string, and always have a time limit.
- Every `git` call is hardened, so the repository's own config and attributes cannot run code.
- A change that adds a new external command adds it to this page in the same change.

The rest of this page is the detailed reference.

Every program outside PHP's own code that Intakt or its checks call, who calls it, and whether you need it. A change that adds a new external command adds it here in the same change.

## To run Intakt

Only **Docker or Podman**. The container image (`Dockerfile`, plan task T22) ships everything below that Intakt needs at runtime; building it calls `docker build`, which needs the same Docker CLI and daemon as above. The demo (`compose.yaml`) runs with `docker compose up`, which needs Docker Compose v2.24 or later (an `env_file` entry with `path` and `required`).

## When a tool is missing

Before it runs any gate, `bin/check` looks up the commands of the selected gates by name on `PATH`, as `config/gates/src/RequiredTools.php` lists them:

| Gates | Commands looked up |
|---|---|
| every gate | `git`, `sh`, `setsid` (each gate runs in a child process of its own session) |
| `audit` | `composer` |
| `journeys` | `sh`, `env`, `setsid`, `unshare`, `true` |
| `tests` | `sh`, `unshare`, `setsid`, `true`, `bash`, `jq` |
| `secrets`, `secrets-history` | `gitleaks`, `env` |

Only the gates that `--only` and `--skip` leave selected count: a command only a skipped gate needs is not looked up, and when they leave no gate selected nothing is looked up, `git` included. When `INTAKT_GITLEAKS` is set, its value replaces `gitleaks` in the lookup and in the message; a value with a `/` is checked as a path to an executable file, a relative one from the workspace root (`--root`, else the repository) where the secrets gates run it. A value that names a command another selected gate needs (such as `env`) is still listed once. A name without a `/` is looked up as starting it in the workspace root does: the `PATH` entries are walked in order, an absolute entry as it is and a relative or empty entry (such as `tools` or `.`) from the workspace root, an empty entry being the root itself; the first entry that holds an executable file of that name makes the command present, and none makes it missing. A command only under a relative entry of the directory `bin/check` was started in therefore counts as missing, unless a later entry holds it. When `PATH` is unset, the entries are the default path of `/bin/sh`, because Symfony Process hands every gate command to `/bin/sh` as `exec <arguments>` and that shell then searches its built-in default path; the preflight reads it by starting `/bin/sh -c 'printf %s "$PATH"'` with `PATH` removed (`/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin` with dash). If that shell cannot be started or fails, only the workspace root is searched.

When any gate is selected, it also checks that PHP's `pcntl` and `posix` extensions are loaded (`pcntl_signal()`, `pcntl_waitid()`, `posix_kill()` and `posix_getpgid()` exist, so one of them disabled through `disable_functions` counts as its extension missing): each gate's child runs in a session of its own, which a Ctrl-C at the terminal does not reach, so `bin/check` needs `pcntl` to pass SIGHUP, SIGINT and SIGTERM on to the child's group and to ask whether the child's launcher is still its unreaped child, and `posix` to read the launcher's group and signal it (`ProcessGroup::FUNCTIONS`). The stop also reads the launcher's start time from `/proc/<pid>/stat`, so `/proc` must be readable by PHP (not outside `open_basedir`); a PHP process that starts a gate child or a contained run checks the functions and `/proc` itself and refuses the start with `cannot run <program>: ...` when one is missing. A missing one is listed as `PHP extension <name> not found, see docs/architecture/requirements.md`, after the commands. When any command or extension is missing, no gate runs: `bin/check` prints one JSON line naming every missing command once, `{"error":"missing tools","missing":["<command> not found, see docs/architecture/requirements.md", ...]}`, and exits with 2. When the `audit` gate is selected and `composer` is found, the same list names a Composer older than 2.11, which would ignore `config.policy.cooldown`: the preflight runs `composer --version --no-ansi --no-plugins --no-interaction` in the workspace root and adds `composer <version> found, 2.11 or later is required for policy.cooldown, see docs/architecture/requirements.md`, `composer reports no version, ...` when its output has no `Composer version x.y.z` line, or `composer version could not be queried, ...` when the process cannot be started (so the check fails closed), after the missing commands and before the missing extensions. A `gitleaks` that is found but is not the version `GitleaksGate::PINNED_VERSION` names still fails the secrets gates with their own message (`gitleaks <version> is required, set INTAKT_GITLEAKS to it or put it first on the path, an override is checked too, see docs/architecture/requirements.md`).

When `bin/probe` isolates with `unshare` (`PROBE_ISOLATED` is not `1`), it looks up `unshare`, `sh` and `ip` on `PATH` before it starts anything, resolving a relative or empty entry in the project root, where it starts the run, and searching `/bin:/usr/bin` when `PATH` is unset, as the process start does; for each missing one it writes `<command> not found, see docs/architecture/requirements.md` on its own line to standard error and exits with 2.

Tests: `tests/Gates/RequiredToolsTest.php` (every missing command listed once, a gate not selected requires nothing, the `tests` gate needs `bash` and `jq`, the `journeys` gate alone names a missing `unshare` and `true`, the override is looked up instead of `gitleaks`, a relative override is found in the workspace root, an override naming another required command is listed once, a command under a relative `PATH` entry of the workspace root is found and one only under such an entry of the caller's directory is listed, one under such an entry of the caller's directory and a later absolute entry is found, with `PATH` unset a command on the default path is found and one off it is listed, with `PATH` unset only the commands a gate's process cannot start are listed, and with `PATH` unset and no way to start a process only the workspace root is searched, the message, a Composer 2.10.4, one that reports no version or one whose version cannot be queried is refused and 2.11.0 is accepted), `tests/Gates/GateChildExtensionsTest.php` (`bin/check` started with `pcntl_signal` or `posix_kill` disabled exits with 2 and runs no gate, and runs the gate when both exist) and `CheckCommandTest::testMissingToolsAreListedBeforeAnyGateRuns`, `testAMissingToolOfAGateThatIsSkippedDoesNotStopTheRun`, and `ProbeTest::testAProbeNamesEveryMissingToolBeforeAnythingStarts`, `testAToolUnderARelativePathEntryIsFoundInTheProjectRootWhereverTheProbeIsCalledFrom`, `testAToolInTheProjectRootIsFoundThroughAnEmptyPathEntry`, `testAToolOnlyUnderARelativePathEntryOfTheCallersFolderIsNamed`, `testWithoutAPathVariableAToolInTheDefaultSearchPathIsFound` and `testAnEmptyPathVariableSearchesOnlyTheProjectRoot`.

## How Intakt calls them

- **Through Symfony Process with an argument list, never a shell string:** the local git forge, the gates (through their runner) and the upstream reproduction runner. `bin/instance` and `bin/probe` start their processes with PHP's `proc_open` and an argument list; where they use `sh`, the command after it is passed as separate arguments.
- **With a time limit** on every call made through Process.
- **Every `git` call is hardened** the same way, in the local git forge and in the gates: the repository's own config and attributes can run no code and change nothing that is read ([below](#the-hardened-git-call)).

## The hardened git call

A builder writes the repository content Intakt later reads with `git`, so the repository's own config and attributes must never run code or change what is read. Every `git` call is built by one of two equal classes: `Core/Git/Contract/HardenedGit` for the local git forge (`Plugin/LocalGitForge`), and `config/gates/src/HardenedGitCall.php` for the gates (`ProcessRunner::git()`, reached through `Workspace::git()`). The gates keep their own copy because `config/gates/` is a protected path, so no builder can weaken how a gate reads the repository; `tests/Gates/HardenedGitCallTest.php` fails when the two build a different command or environment. No other code starts `git`.

`call(directory, ...arguments)` returns a `GitCall`, a typed object with the argument list (no shell), the absolute directory the process runs in, and the environment; `callWithPathspecMagic()` does the same without `--literal-pathspecs`. `HardenedGit` takes the directory first and the arguments after it, and its `GitCall` holds the argument list as a `GitCommand` and the environment as a `GitEnvironment`, which a caller spreads into the Process; the gates' copy keeps `call(arguments, directory)` and plain arrays. `environment(directory)` alone serves a tool that starts `git` itself (gitleaks). The argument list:

```
git --no-replace-objects --no-lazy-fetch --literal-pathspecs
    --attr-source=<empty tree>
    -c core.hooksPath=/dev/null -c core.fsmonitor=false
    -c diff.external= -c core.attributesFile=/dev/null
    -c log.showSignature=false
    -c gpg.program=/dev/null -c gpg.ssh.program=/dev/null -c gpg.x509.program=/dev/null
    -c i18n.logOutputEncoding=UTF-8 -c core.ignoreCase=false <arguments>
```

- `--no-replace-objects`: a `refs/replace/` ref cannot swap in another commit or blob.
- `--no-lazy-fetch` (git 2.45 or later; an older git refuses the option, so every call fails): a partial clone (`extensions.partialClone`) fetches no missing object, so the transport of a promisor remote the repository config names (an `ext::<command>` URL with `protocol.ext.allow=always`, say) never starts; the call fails on the missing object instead (`Not a valid object name`, which the forge turns into `ForgeReadFailed`).
- `--literal-pathspecs`: a path is read as its exact name, so a leading `:` is not pathspec magic. `callWithPathspecMagic()` leaves it out for the two gate calls that pass their own `:(glob)` pathspecs, never a path from the repository.
- `--attr-source=` git's empty tree in the repository's object format (`4b825dc642cb6eb9a060e54bf8d69288fbee4904` for SHA-1, `6ef19b41225c5369f1c104d45d8d85efa9b057b53b14b4b9b939dd74decc5321` for SHA-256): no `.gitattributes` of the repository applies (no filter, diff driver, `binary` or `eol` attribute from the tree). The format comes from `git rev-parse --show-object-format`, asked together with the `info/attributes` check below; when git cannot answer, or names a format other than these two, the SHA-1 tree is used, which git refuses in another format, so a command that consults attributes fails with `bad --attr-source` instead of reading them.
- `core.hooksPath=/dev/null`: no repository hook runs.
- `core.fsmonitor=false`: no repository fsmonitor command runs.
- `diff.external=` and `core.attributesFile=/dev/null`: no external diff command and no attributes file outside the repository.
- `log.showSignature=false` and the three `gpg.*program` settings: `git log` and `git show` verify no signature, so a commit with a `gpgsig` header never starts the gpg, ssh or x509 program the repository config names. A call that asked for `--show-signature` would try to run `/dev/null` and report that failure instead.
- `i18n.logOutputEncoding=UTF-8`: commit messages are printed as UTF-8, so an encoding such as `ASCII//TRANSLIT`, which turns a long dash into `--`, cannot rewrite a subject before the commit gates read it.
- `core.ignoreCase=false`: paths compare case-sensitively, so a repository's `core.ignoreCase=true` cannot hide an untracked `SAFE.php` beside a tracked `safe.php` from the untracked listing.

`environment(directory)` gives the environment of the process, or throws `RepositoryAttributesRefused`. The directory is made absolute first (`realpath`; a directory that does not exist stays as given, and the call itself fails there), because the process changes into it before git reads `GIT_WORK_TREE`, so a relative one, such as a relative `--root` of `bin/check`, would be resolved twice and `git status` would report that it must run in a work tree:

- The repository is refused when `$GIT_DIR/info/attributes` exists. Git reads that file on top of every other attributes source, and no option, setting or variable switches it off, so a `-diff` line or a `diff=<driver>` line there could show a changed file as `Binary files differ` or select a driver from the repository config. The file is located with `git rev-parse --show-object-format --git-path info/attributes`, run hardened, so the common directory of a worktree or a submodule is found too; when git cannot name it, the directory is no repository and the call itself fails. The forge turns the refusal into a `ForgeReadFailed`; `bin/check` reports it as the failure of every gate that reads git, with the reason. The check runs when the call is built, right before it, so a file written between the two is not refused; what such a file could still do is closed by the calls themselves (below).
- Every inherited `GIT_*` variable is removed (such as `GIT_DIR` inside a git hook).
- `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, and `HOME` and `XDG_CONFIG_HOME` set to a path that does not exist, so neither the system nor a user config is read.
- `GIT_NO_REPLACE_OBJECTS=1`, `GIT_ATTR_SOURCE` set to the empty tree and `GIT_ATTR_NOSYSTEM=1`, set after the inherited variables are removed.
- `GIT_NO_LAZY_FETCH=1`: the same as `--no-lazy-fetch`, for a tool that starts `git` itself.
- `GIT_ALLOW_PROTOCOL` set to the empty string: the variable is an allowlist that beats every `protocol.<name>.allow` of the repository, and an empty one allows no transport (`transport 'ext' not allowed`), so no remote helper, `core.sshCommand` or credential helper the repository names can run from any fetch. A `-c protocol.allow=never` would not do, because the repository's more specific `protocol.ext.allow` wins over it.
- `GIT_GRAFT_FILE` set to a path that does not exist: a `.git/info/grafts` file cannot give a commit other parents, which would hide the commits in between from `git log` and `git rev-list` as a replace object would.
- `GIT_WORK_TREE` set to the directory the call runs in: a `core.worktree` in the repository config cannot point working-tree reads (changed and untracked files) at another directory.
- The ten `-c` settings as `GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_n` and `GIT_CONFIG_VALUE_n`.

`callInBareRepository(repository, ...arguments)` is the call for a bare repository, or for a git directory used without its work tree (the mirror, a checkout's `.git`). No caller sets `GIT_WORK_TREE` itself: every caller that reads or writes only objects and refs uses this call, and an `init` names its new `--git-dir=.git` so the pinned work tree is accepted. It keeps every option, setting and variable above, but runs in the repository with `--git-dir=<repository>` (made absolute) and `--bare` before the arguments and `GIT_WORK_TREE` unset, so git takes no work tree. The `info/attributes` check is the same, run with the same pin, and asks `--show-cdup` too: a `core.worktree` of a repository whose `core.bare` is `true` is ignored by git, but beside a `core.bare = false` of the repository's own config it beats `--bare`, and git then prints a way to that work tree. Such a repository is refused with a Process `RuntimeException` (`<repository> names a work tree in its config (core.worktree), so a bare call refuses it`), which every caller already handles as a failed git call, so a `core.worktree` never applies to a bare call that is prepared against that config. The guarantee covers preparation only: git rereads the config when the command runs, so a config changed between the preparation and the run is not seen by the check. A repository that does not exist is not checked, and the call itself fails there.

With the tree's `.gitattributes` replaced by the empty tree, the attributes file and the system attributes switched off and `info/attributes` refused, no attribute reaches a call. An `info/attributes` written after the check could still name a driver, so no call depends on the refusal alone:

- Every call that shows a diff passes `--text --no-ext-diff --no-textconv`: the forge's diff and the gitleaks history gate's `git log` (also handed to gitleaks), and the `git log -G` searches of that gate. Every file is shown as text, so neither an attribute nor git's own detection replaces a change by `Binary files differ`, and no textconv or external diff driver runs. The forge then names a file whose base or head blob holds a NUL byte anywhere as binary with its sizes (`git cat-file blob`), so its bytes leave the diff, and escapes each byte that is not UTF-8 in every other file, which keeps all its lines (see [forge contract](forge-contract.md)). The GitHub forge's held-change diff (`MirrorChange`, also with `--text --no-ext-diff --no-textconv`) names only a plain image (mode `100644`, a PNG, JPEG or GIF by name and first bytes) the same way and leaves every other file's bytes unescaped, so the push request refuses one that is not UTF-8 or holds a NUL byte (see [Workflow risk scan](workflow-risk-scan.md#holding-the-push)). A file read (`fileAt`, `fileAtHead`) names a blob with a NUL byte anywhere as binary with its size the same way, instead of returning its bytes.
- No call reads the working tree through a filter. The gates' changed paths (`Scope::changedPaths()`) compare the index with the base by `git diff-index --cached`, then hash the tracked files with `git hash-object --no-filters` and compare those hashes and the owner's execute bit with the blobs and modes of `git ls-files --stage`, so a mode-only change counts as changed; an entry that is conflicted, a link or a submodule, or whose file is missing or not a regular file, counts as changed. So no clean filter runs, whatever attributes git sees. The forge reads commits and trees only.
- The gates list untracked files (`Scope::changedPaths()`, and the repository files of `Scope::allPhpFiles()`) with `git ls-files --others --exclude-per-directory=.gitignore`: only the `.gitignore` files of the tree exclude a file, never `info/exclude` or a `core.excludesFile` of the repository config, which no diff shows.

Tools that start `git` themselves get the same protection from the environment: the gitleaks gates pass it, so gitleaks's `git log -p` reads no replacement object or graft and applies no attribute.

Not covered: settings that only change how git formats what it prints (`diff.noprefix`, `diff.srcPrefix`, `diff.dstPrefix`, `diff.algorithm`, `core.abbrev`) are left as the repository sets them; a patch stays a correct patch, and the gates read paths with `-z` and hashes and subjects with `--format`.
