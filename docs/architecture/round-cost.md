# Round cost

What a review round's model calls cost, from a price per model in the owner's config ([Budget and model planner](../design/05-architecture/06-budget-and-model-planner.md): a model missing from the table shows no price, never an estimate). The cost plan task T13's `intakt:review` prints; issue #1107 part 1 (the console) and part 2 (the dashboard, from the same value).

- **Config:** `budget.prices.<model>` in `config/intakt.yaml`, beside the ceilings, processed by `Core/Budget/Infrastructure/BudgetConfiguration` (formerly `CeilingsConfiguration`, see [Measured use](measured-use.md)): keys not normalized, so a model name keeps its dashes and dots; `input` and `output` required, `cache_read` and `cache_write` optional and set to `input` when left out; each a float of at least 0, in US dollars per million tokens; an int becomes a float, and a NaN or infinite float becomes a string before normalization so the type check refuses it (Symfony Config before 8.2.0-BETA2 skipped every check for NaN, a bug fixed upstream, see `upstream/config-nan-skips-validation/`; the step is kept as a workaround). `config/packages/ai.php` puts the result in the parameter `intakt.budget.prices` (`BudgetServices::PRICES`). No `prices` key means an empty table.
- **Price date:** the optional `budget.price_date` (a quoted `YYYY-MM-DD`, validated by `BudgetConfiguration`, which refuses anything but a string, because Symfony YAML parses an unquoted date to a timestamp and moves an impossible day such as `2026-02-30` to `2026-03-02` first; parameter `BudgetServices::PRICE_DATE`) is read by `ConfiguredPrices` and carried by each priced `Cost` as `priceDate`; `Cost::plus()` keeps it when both parts are priced. `Cost::unknown()` (also the sum with an unknown part) and `Cost::none()` carry no date, so the JSON's `price_date` is `null` for them.
- **Contract:** `Core/Budget/Contract/Prices::costOf(?string $model, TokenFigures $figures): Cost`. `Cost` holds `usd` (a float, or null when unknown), `priceDate` and `unpriced` (the models without a price, each once). `Cost::plus()` adds two known costs; a known plus an unknown is unknown and keeps the models of both, so a round with one unpriced call never shows a partial sum or 0. `Cost::none()` is 0 (a round without calls).
- **Implementation:** `Core/Budget/Infrastructure/ConfiguredPrices` reads the parameter. For a model in the table the cost is `(prompt - cacheRead - cacheWrite) * input + cacheRead * cache_read + cacheWrite * cache_write + completion * output`, divided by a million, on the `TokenFigures` of [Vendor](vendor.md#token-figures); the combined `cached` figure (Claude Code) stays in the input part, because it does not say which of the two cache prices applies. A model not in the table, and a call whose `started` row has no model (named `ConfiguredPrices::NO_MODEL`, `(no model)`), give `Cost::unknown(model)`.
- **A round's cost:** `Core/Review/UseCase/ReviewChange/RoundLedgerReading::costOf(roundId)` finds the round's calls exactly as `tokensOf()` does (the `started` `usage_recorded` rows carrying the round id, and the `settled` or `unsettled` row of each call) and prices the summed `TokenFigures` of each call's usage entries by the `model` of the call's `started` row (the model its tier resolved to, see [Vendor](vendor.md)), because a round's reviewers and its judge may run on different models, and the `model` of a usage entry is what the vendor's answer names: none for Claude Code and Codex, a dated snapshot such as `gpt-5-2025-08-07` for an API. A call with no usage entries is priced as zero tokens: it adds 0 when its model has a price and makes the cost unknown when it has none. A call with a usage entry whose `prompt` is null (the provider reported no input tokens) is priced and then added to `Cost::unknown()` with no model, so the round's cost is unknown instead of the output-only sum, and still names the call's model when it has no price. `RoundLedgerReading` implements `Core/Review/Contract/RoundCosts`: `costsOf(roundIds...)` prices several rounds from one read of the `usage_recorded` rows into a `Contract/RoundCostList` (a round without calls costs 0, one not asked for is refused), and `costOf()` is the same computation for one round. The dashboard's `LedgerRounds` uses the interface and prices all rounds of a review with one `costsOf()` call; `ReviewChange` calls the same `RoundLedgerReading` directly (for `Contract/ChangeReview::$cost`), because it also needs `tokensOf()` and the judge's act ids, which the interface does not carry. So there is one computation.
- **Wording:** `Cost::reading()` is the one text of a cost, used by the console and the dashboard (each passes how it makes a model name safe: `VisiblePath` for the console, Twig escaping for the page).
- **Console:** `Plugin/LocalGitForge/UseCase/ReviewChange/ReviewReport` prints `cost: 0.0459 USD estimated, prices of 2026-11-13` (four decimals; `cost: less than 0.0001 USD estimated, ...` for a cost above 0 that rounds to 0.0000; `price date unknown` replaces the date when `budget.price_date` is not set, and for a round without calls, whose `Cost::none()` carries no date) after the token line, or `cost: unknown, no price for <models>` (each model name through `VisiblePath`, because a model name comes from the ledger), or `cost: unknown` when no model is named (a row without input tokens, a recorded loop round). The JSON (`ReviewOutput`) carries `cost` with `usd`, `unpriced` and `price_date`, and `kinds` (`round`, `findings` and `calls` counted, `tokens` measured, `cost` estimated; `docs/user/review-output.schema.json`). A cost line that shows no figure (unknown) has no kind marker. The kinds come from `Core/Platform/Contract/FigureKind` (the marker is the case's value) through `ReviewOutput::KINDS`, which both the text and the JSON read, and `Figures::marked()`; `Figures::total()` throws `MixedFigureKinds` over figures of different kinds, so a sum of tokens and cost is never printed. The round line reads `changes (round 1 counted)`, each finding count reads `2 findings counted`, and the token line reads `5 calls counted, ... total measured`, because the call count comes from the ledger's rows and the token figures from the provider's usage answers. The dashboard's review page uses the same `FigureKind` cases (#2089, see [Dashboard](dashboard.md)) for at most three labels since #2206: `estimated` after the review's cost in its summary line, and in the newest round's tables `counted` on the `Findings` head and `estimated` on the `Cost` head; its token counts, round count and costs in the tables carry none. Each cost with a figure shows its price date (#2090), in the console's wording: the date part (`prices of <date>` or `price date unknown`) has one home, `Cost::priceDateReading()`, which `ReviewReport` and the dashboard's `components/cost.html.twig` and `components/cost_plain.html.twig` call.
- **Seeded prices:** `SampleProject` (`Core/Review/UseCase/SeedSampleProject`) writes a top-level `budget.price_date` and a `budget.prices` block next to `projects:` in the seeded file, both from the sample project's data file `config/sample-project.yaml` (shipped: 2026-11-13), holding the list price of each distinct model its tiers name, and no other; a model the data file does not price is a `LogicException`, so a new seeded model needs a price in the same edit of that file ([the demo](demo-with-docker-compose.md)). There is no built-in price table: an unseeded or older file still gives unknown.
- **Not yet:** the one `price_date` dates the whole table, and prices are not fixed when a call is admitted (the design's dated table): a round is priced at the table in the current config; the cost is not live over Mercure, and the job, task and project cost views are planned.
- **Tests:** `tests/Core/Budget/Contract/CostTest.php`, `tests/Core/Budget/Infrastructure/ConfiguredPricesTest.php` (a recorded Anthropic usage answer through Symfony AI's Anthropic `TokenUsageExtractor`, priced and unknown; an OpenAI-form answer; unsplit cached tokens; a row without a model), `tests/Core/Budget/Infrastructure/BudgetConfigurationTest.php`, `tests/Core/Review/UseCase/ReviewChange/RoundLedgerReadingTest.php` (a Claude Code answer through its `TokenUsageExtractor`, which names no model, and an API answer naming a dated snapshot, both priced by the tier's model; a call started without a model; a usage without input tokens is unknown, one with 0 input tokens is priced; several rounds priced from one read, each by its own calls, with an unknown kept to its own round) and `ReviewChangeTest.php`, `tests/Plugin/SymfonyAiVendor/SymfonyAiVendorTest.php` (the started row names the tier's model, or the substitute's), `tests/Plugin/LocalGitForge/ReviewReportTest.php` (the `cost:` line and the schema) and `ReviewOutputTest.php`, and `tests/Application/ProjectTiersTest.php` (the file's prices reach the parameter).
