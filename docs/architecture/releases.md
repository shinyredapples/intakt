## Releases

`.github/workflows/release-labels.yml` labels each pull request from this repository (it skips a pull request from a fork on every trigger) `feat`, `fix` or `docs` from its title type and removes a stale one, reading the labels at run time. It runs when a pull request is opened, reopened or edited (`opened`, `reopened`, `edited`), and its `label` job skips an edit that leaves the title alone (`github.event.changes.title`), so a title change relabels at once. It does not run on a new push, because the label follows the title, not the commits. A later run for the same pull request cancels a running one (concurrency on the job, so a skipped edit cancels nothing). The `label` job runs on GitHub's `ubuntu-24.04`, never on `CI_RUNS_ON`, because it uses that image's `gh`, which a `CI_RUNS_ON` runner need not have. `.github/release.yml` groups the generated notes by those labels. `tests/Gates/ReleaseLabelsTest.php` runs the workflow script against a fake `gh`, and `tests/Gates/ReleaseLabelsTriggersTest.php` asserts the workflow's `on:` block. Details: [Releasing](../releasing.md).
