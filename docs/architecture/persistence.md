## Persistence

SQLite by default (`DATABASE_URL` in `.env`). MySQL, MariaDB and PostgreSQL are supported targets: the `persistence` job in `.github/workflows/ci.yml` runs `vendor/bin/phpunit --group persistence` on MySQL, MariaDB and PostgreSQL, in the versions `.github/ci/databases.Dockerfile` pins (one job with a service container per engine, its data directory on a tmpfs, and one step that runs the three engines at once through `.github/ci/persistence-engines.sh`, each reached by its service name `mysql`, `mariadb` or `postgresql`, no password; one job instead of a three-entry matrix because each job costs an ephemeral runner a full reset; the test environment appends `_test` to the database name, so the URL names `intakt` and the service creates `intakt_test`). On a pull request the engines run only when the `changes` job finds the change touches persistence: a path under `src/Core/Ledger/`, `src/Core/Platform/` (the database platform and server version), `migrations/`, `tests/Core/Ledger/`, `tests/Core/Platform/`, Doctrine's configuration, the Composer files, `phpunit.dist.xml`, `tests/Application/MigrationsMatchMappingTest.php`, `.github/workflows/` or `.github/ci/`, an added line naming Doctrine in `src/`, or a test it adds, removes or edits in the `persistence` group (a changed line or file under `tests/` naming `Group('persistence')`); `.github/ci/persistence-needed.sh` decides, and its diffs are saved and must succeed first, so a failure fails the `changes` job and the run rather than reading as untouched. On every push to main they always run. `bin/check` still runs the whole suite on SQLite. In the test environment every SQLite connection of the container runs `PRAGMA synchronous = OFF` when it connects (`tests/Support/UnsyncedSqlite.php`, a DBAL middleware that `tests/Support/services.yaml` tags `doctrine.middleware`; a connection to another engine is left as it is), so a test does not wait for the disk after each statement on its scratch database file. `doctrine.dbal.server_version` comes from the `postgresql_server_version` env var processor (`src/Core/Platform/Infrastructure/PostgreSqlServerVersion.php`) applied to `DATABASE_URL`: a PostgreSQL URL (driver `pdo_pgsql`, or `pgsql` through `?driver=pgsql`) gets `12`, the version of DBAL 4's newest PostgreSQL platform, and any other URL none, so MySQL, MariaDB and SQLite detect the server on the first connection. DoctrineBundle picks a platform before it connects and refuses an empty PostgreSQL version (`upstream/doctrine-bundle-postgresql-empty-server-version`); `tests/Core/Platform/PostgreSqlServerVersionTest.php` builds the test connection for both PostgreSQL drivers and for MySQL. `migrations/` is in Composer's `autoload-dev` (`DoctrineMigrations\`), so tests and static analysis name a migration class directly; the migrations bundle still finds migrations by path.
