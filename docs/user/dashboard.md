# The dashboard

Intakt's dashboard shows your projects, their reviews, the page of one review and the steps of one task in the browser. This page describes each page, the Trends page, live updates, the status document and the UI check that tests the pages.

## The dashboard

Intakt serves eleven pages in the browser (among them the Status page at `/lanes`, reached from the board's status line, and the demo run's `/demo`, see [Playing the demo run in the dashboard](demo.md#playing-the-demo-run-in-the-dashboard)), built from the ledger of review events and of the steps of `intakt:build:task` (no model call) and, for the forge budget on `/reviews`, from the budget GitHub's own answers last reported (no forge call). The dashboard's own address (`/`, for example `http://localhost:7781` in the container) shows the board, except on the demo (an install with the sample repository) before any review has run, where it sends you to the first-run page (`/setup`, see [The demo with docker compose](README.md#the-demo-with-docker-compose)). On a phone (a browser that sends the hint `Sec-CH-UA-Mobile: ?1`, or whose user agent contains `Mobi`, as iPhone Safari and Firefox on Android do), the address opens **Waiting on you** (`/waiting`) instead, also from a link in another app, unless the install is quiet: when the board holds at least one review, every card on it is Done, nothing is running (no review and no build) and nothing waits on you, it opens the newest review instead, so a board with no review yet still opens Waiting on you; the demo's first-run page still comes first. The Now entry of the menu, **Back to the board** and **Show N more** open the board on a phone too (they link to `/?board=1`), while the Intakt logo opens the dashboard's address. The board has nine columns (Waiting on you, Backlog, Ready, Planned, Building, Checking, In review, Merging, Done) and shows them side by side, each with its name and the number of cards in it across all projects. Waiting on you, In review and Done are always shown. The other six hold the tasks of features that do not run yet, so while one of them holds no card it is left out, and one line above the columns, starting with a small **Coming next** chip, names the left-out ones instead, for example "Backlog, Ready, Planned, Building, Checking and Merging show here once a task is in one of them"; the line is text, not a button. Once such a column holds a card, the next load of the board shows it again in its place. Under the title "Board", one line in muted text says what is going on: "Nothing is running yet. Start the first review." on a new install, a link to the first-run page; otherwise which changes the Code reviewers are reviewing (or, with no review running, "A build is running." or "N builds are running." while builds work on tasks, else "Nothing is running.") followed by "Nothing needs you.", or by the number of things that wait for you in the amber count of Waiting on you, "need you:" and a "see what" link (the count follows the board's Waiting on you column, which holds no card yet, so the line says "Nothing needs you." even while the Waiting on you page, below, lists an outage). While a review runs, the part that names what the Code reviewers are reviewing is a link: clicking it opens the review page of the first change it names. It keeps up as reviewers start and rounds change while the live connection is up. On a phone (narrower than 761 pixels) it counts the running changes instead of naming them ("The Code reviewers are reviewing 3 changes."), so it stays within two lines; the Status page names them. Each change under review is one card, in In review while its latest round runs and in Done once that round is judged; the card shows the change's number, its project, once the latest round has an outcome that outcome as its headline (**Approved**, **Changes requested**, **Blocked** or **Failed**, with its icon, in larger type on its own line above the title), "Review of" the change, its round (with the word's explanation when you point at it), the number of reviewers and the cost so far, and opens the review page of its latest round. A round from before Intakt recorded its change shows its round id instead. A card whose latest round (the one it shows and opens) was stored as a replay (a recording played back for the demo) carries a **Replay** label beside its project: that round's verdicts were never given on the change and never count as one. Each round keeps its own mark: a round started before its project was marked as a replay stays live, so a card whose latest round is live has no label, and a replay round started after a live round of the same change gives its card the label. Waiting on you is pinned as the first column and is a little wider than the others; it is meant for cards that wait for you, and since no card waits there yet (the outage notices Intakt records are listed on the Waiting on you page, below, not as cards), it holds no card and counts 0. Every column on the board without a card, on a new install and after, says in one line what will appear in it and when, for example "What only you can decide appears here when Intakt asks you" in Waiting on you and "Reviews appear here while a panel reviews a change" in In review. On a new install, before any review has run, a **Set up Intakt** button beside **Open the review list** opens the first-run page (`/setup`, below); once a review has run, the button is on the Projects page instead, and `/setup` still answers at its address. The project filter hides the cards of other projects; the counts stay the totals. A column with more than 12 cards shows its first 12 and a **Show 28 more** button (the number is the cards left) under them, which shows the rest; with a project chosen, the 12 and the number count only that project's cards, the button disappears when 12 or fewer are left, and choosing a project never folds an opened column back. When a column changes while the board is open (a review starts or is judged), the live update brings only its first 12 cards; the button is then a **Show 3 more** link that reloads the board, where **Show more** shows the rest, and its number counts the cards left out of every project, also with a project chosen; a column you opened with **Show more** shows its first 12 again. A long title wraps to at most three lines and a long change number or project name on a card is cut short with "…"; pointing at the number or the project name shows it whole. With many projects (the board is checked with six), every card, lane and banner names its project in words, never by a color, the project filter is a list that holds any number of them, and only the columns scroll sideways, never the whole page. Backlog (once it holds a card and is shown) and Done start collapsed, each to a 108 pixel strip with its name and count side by side; clicking the strip opens the column with its cards, and **Hide** in its heading collapses it again (each page load starts them collapsed). Only when every other column is empty, as after the demo, does Done start open, and the board starts scrolled to its right end, where Done is, so its cards show without a click or a scroll. When the columns are wider than the window, the side with hidden columns fades out (the right edge first, the left one too once you scroll right), so you can see there is more. On a phone (narrower than 761 pixels) they are not collapsed: every column shows its cards. **Open the review list** leads to `/reviews`. From 1700 pixels of width every dashboard page and its top bar leave 48 pixels at the sides instead of 32; the board has no maximum width and grows with the window at every width. On a phone the word "Round" on a card, which the keyboard reaches on its own, is 44 pixels tall like every other control. The row of columns itself takes the keyboard's focus with Tab, so the arrow keys scroll it sideways, also when it has no card yet; the board passes the UI check (below) at every width in both themes.

Above the columns, the board shows one quiet status line: "Running smoothly · N reviewers working" ("1 reviewer" for one), with ", N builds running" ("1 build") added while builds of `intakt:build:task` are in flight ("Running smoothly · 1 build running" when no reviewer runs), or "Quiet · nobody working" while neither runs. It links to the **Status** page (`/lanes`, reached from the line; Now stays marked in the menu), which repeats the line and lists the lanes: the reviewers still running in the latest round of each review that the judge has not decided and that has not ended as **Blocked** (see the review page below), newest review first, each with a green dot and a small meerkat head (only a picture, which screen readers skip) before its role and tier, the time it started (UTC), its change, its project and its round. Each lane links to the review page of the round it is working on. In a narrow lane the role, tier and start time wrap onto further lines instead of running into the next lane. With no lane, the page says what will appear there: "No reviewer is working right now: reviewers appear here while they review a change". The project filter hides the lanes of other projects, but the count stays the total over all projects. Build slots, runners and budgets are not part of it yet, so there is no idle count and no total.

Above the status line, the board shows one red banner for each pull request whose head failed in the watcher (the same heads as "Pull requests that failed" on `/reviews`): "Pull request 7 of alpha failed.", then how many failures in a row and the next try (UTC), or that it was handed over to the maintainer agent, and the cause, with any credential in it replaced by `[redacted]`. **See the failed pull requests** opens that section of `/reviews`. The project filter hides the banners of other projects. The board does not update them live: a banner goes away on the next load of the board after the watcher reads the head again, starts its round or forgets the pull request. Below 761 pixels a banner is one line with the pull request and project; tapping it shows the rest, also on a board without the live connection, and tapping it again closes it.

**Waiting on you** (`/waiting`) lists every item only you can act on, oldest first. Today the only such items are usage outages: an AI account whose usage Intakt has not read for 3 hours since its last reading (the same outage it warns about in its log, see [Cooldowns, pauses and outage notices](running.md#cooldowns-pauses-and-outage-notices)). An item stays only while the outage lasts: once a newer usage reading of that account arrives, the item leaves the page on its next load (nothing is deleted). The newest reading counts by the time it was taken, not by when it was stored: an older reading that is stored late, after a newer one has cleared the outage, never replaces the newer one, so the item does not come back. Each item is a card with the Maintainer (a tortoise, with its name "Maintainer" written beside it); a first line saying what waits ("No usage of account claude_code.main has been read since 2026-11-02 08:00 UTC"); a line with "All projects" (an outage concerns every project, so the project filter never hides it) and how long it has waited ("Waiting 2 h 5 min"); what happens meanwhile (the budget guard starts at most one call at a time on that account, and none while any of its five-hour or weekly windows that has not reset yet stands at its limit, so builds queue); and one button saying what happens next. The button opens the public status page of the account's provider (Anthropic's for Anthropic and Claude Code accounts, OpenAI's for OpenAI and Codex accounts) and says that it shows whether the provider reports trouble; other providers have none, so their button reads "See the queue on the board" and says that it shows the build queue on the board (the board has no filter for one account). Both add that the card leaves when readings return, because readings usually return by themselves. The octopus waits once at the top, beside how many things need you; a card has an amber edge. From 1100 pixels wide the button sits on the right of the words; on a narrower window everything is one column with the button last. When nothing waits, the page says **Nothing needs you**. Answering an item on the page itself comes later.

Beside the list, from 1500 pixels wide, or under it on a narrower window, the page shows two panels. **Meanwhile** lists the reviews running now, longest running first, each as "`<change>` of `<project>` is in review, round `<n>`" with a link to its review page and how long it has run ("No review is running now." when none runs); building tasks join it later. **You handled today** lists the outages that ended today (the UTC day), newest first, each as "Readings of account `<account>` came back" with the UTC time of the reading that ended it ("Nothing has left the list today." when none did). The items and both panels come from one read, so an outage that ends while the page loads is listed either as waiting or as handled, never as both. The page shows what was true when it loaded; it does not update itself yet, so reload it to see changes.

Every page sits in the same frame. On the left, the menu shows the Intakt logo, which opens the dashboard's address, and one entry per page that is built: today **Now** (the board), **You** (Waiting on you, with an amber count of what it lists when that is not zero), **Trends** and **Projects**, each highlighted while you are on it (the Status page keeps Now highlighted; Team, History and Settings join them as their pages are built). **Collapse** at its bottom narrows the menu to its icons; this browser remembers it. The bar along the top holds the search field, with the hint `Ctrl K` (`⌘K` on a Mac): clicking it, or pressing Ctrl K (Cmd K on a Mac) on any page, opens the search window over the page (see Search, below). Beside it, the moon or sun button switches between the light and the dark look and remembers the choice in this browser. Below 761 pixels of width (a phone) the menu becomes a 68 px bar at the bottom of the screen, each entry an icon over its name (Now, You with its count on the icon's corner, and Trends), and the top bar holds only the logo (it opens the dashboard's address), a **Search** button (it opens the search as a full-screen sheet, described under Search below) and the theme button; the project filter is hidden there, so every project is shown, and the choice comes back on a wider window. Projects sits behind **More** at the end of the bar, which opens a sheet with it above the bar (tap beside it or press Escape to close it); History and Settings join it once built.

- An address that does not exist (for example `/settings`) shows a "Page not found" page in the same frame, with a **Back to the board** button. If Intakt itself fails on a page, the page says so in plain words and shows a short reference to quote when you report it; the details are in Intakt's log under the same reference. Under an address the dashboard does not answer (another name or another port, see below), such a page is plain: the message and the link without the frame, and without the name of any project.
- `/components` shows each building block of the dashboard (buttons, a button with only an icon, segmented tabs, filter chips, cards, banners and the one-line phone banner, inputs, a number stepper, a command with a Copy button, usage bars including a dimmed "Last known" one, the four review outcomes, and so on) in the light and the dark look side by side, with a "Switch theme" button that flips the look and remembers it in this browser. It loads no font, style or script from another website. A review outcome is one of four labels, each with its own icon: "Approved" (the only one with a green check mark), "Changes requested", "Blocked" and "Failed" (the only red one). "Judged" and "In progress" say where a round stands, not how it ended. The reviews list (`/reviews`) shows the same four labels on its rows, and the review page shows them in the one-line heading of each judged round and for each reviewer in a round's table (a reviewer still running or stopped shows that instead, and one that answered without a decision shows "answered"). Its "Characters" section shows the team's drawings in both looks: the code reviewer (a meerkat with a magnifying glass), the judge (an owl with a gavel), the maintainer (a tortoise with a toolbox) and the developer (a beaver with a wrench, which the first-run page shows beside "To fix"), each next to its name, and the octopus waiting, conducting, bowing and asleep. They are decoration only: screen readers skip them and they never move. The review page's "Now" block shows them too: a small meerkat head before each reviewer's line and an owl beside "The judge's call", and so do the live log (a small meerkat head before each reviewer's heading) and each round's "Findings and the judge's call" heading (a small owl), and on the Status page each lane (a small meerkat head after the green dot, before the role); the words stay as they were, and the outcome is still told only by the words and labels. The board shows a tinted block, "Give Intakt its first task", with the octopus waiting inside it, above its heading, until a review or a task has run, and again, without a reload, once the board has no review left (on the compose demo, after `intakt:demo:remove` took away the only replayed one); and the reviews list (`/reviews`) shows it above "No reviews yet" while it has no review. Once a review or a task has run and nothing is running now (every card in Done, no review in progress and no build working on a task, since a running build also keeps the octopus awake), the board shows the octopus asleep under its title instead, 144 pixels high (120 on a phone); while one project rests and another works, it shows only while the project filter shows a resting project, so never on a phone, which has no filter. The block's three steps say to choose **Set up Intakt** and add an AI provider and a project, to start the first review there (it shows up in In review, then in Done once the judge decides), and that reviewers show up on the Status page while they review it. The board keeps its one **Set up Intakt** button. The first-run page (`/setup`) shows the octopus conducting beside its title, and bowing once any round of the first review was approved, even when a later round starts or is sent back. On a review's page, the newest round shows a small bowing octopus beside its outcome line once it is approved, also when it is approved while you watch; older rounds and other outcomes show none, and the "Approved" label in the round's heading and the outcome line stay what tell you the outcome. Its sample sentence explains three words when you point at them or reach them with Tab: "version" says that an approval covers that exact commit only and that a new push needs a new approval, unless it leaves what you approved exactly as it was (marked planned: for a limit like secrets, the same files, unchanged; approving a merge is planned too, and the one approval Intakt asks you for today is the push of a risky CI change, for its exact commit, see [Holding a risky CI change for your approval](README.md#holding-a-risky-ci-change-for-your-approval)), and that a revised CI push held for you always needs its own approval. The segmented tabs, the filter chips and the stepper only show how they look for now: no page uses them yet, so pressing one changes nothing. The Copy button works, here and on the Waiting on you page: pressing the button puts the command on the clipboard and the button says "Copied", or "Copy failed" when the browser offers no clipboard (it does so only in a secure context it allows: HTTPS or a loopback address such as localhost) or refuses it; it says "Copy" again two seconds after it showed its answer, a new press while it shows one starts the two seconds again, and so does the answer to that press when it arrives, and going Back to the page shows "Copy" too. Nothing links to it yet.
- `/projects` lists the projects that started a review, one row each with its name and a line such as "2 review rounds, 1 judged." (how many rounds it has had and how many of them the judge has decided), or says "No project has started a review yet." with a **Set up Intakt** button. Once it lists a project, a **Set up Intakt** button at its top opens the first-run page.
- `/trends` shows figures about the reviews of every project as tiles and three charts, see [The Trends page](#the-trends-page).
- `/setup`, the first-run page, opens with **See a real review**: while the recorded review can play, its **Play the demo run** button is the page's one main button, with the line "1 minute · no key" above it and what it shows below it; otherwise one plain line says that this install has no recorded review and, while the key field below is shown, to add a key there to run one live, or, once a provider has a key, that a live review can be started or opened from the cards below when the **First review** card has a button, and otherwise that no card below can start one yet. Under it the reviewer, the judge and the developer show what a review does (Read, Check, To fix), then **Use your own project** lists three cards, each marked Done, Missing or Not needed: **Add a key here** (with a field to paste one key while none is set, see [Running the demo on a Hugging Face token](demo.md#running-the-demo-on-a-hugging-face-token), the providers without a key and the first project's tiers), **Add a project**, and **First review** (on the compose demo a **Start the first review** button reviews the sample change; once a review ran, **Open the review** opens it). The first card that is neither done nor marked Not needed has an orange ring and the drawing of the role who does it (the maintainer for the key, the developer for the project, the code reviewer for the first review): a card marked Not needed is skipped, since there is nothing to do in it, and when every card is done or not needed none has the ring. The page shows no command to copy and no MCP address: connecting your own agent is described in [MCP](mcp.md). Connecting a repository, creating the GitHub App and adding an account in the browser are not on it: they are done in configuration today (see [Intakt's GitHub App](README.md#intakts-github-app)).
- `/reviews` lists every round, newest first, one row each, titled by its change and round number ("sample-change, round 2"; "Unnamed change" or "round not numbered" for a round started before Intakt recorded them). A round with an outcome leads its row with it, before the title, as a label with its icon in larger type (**Approved**, **Changes requested**, **Blocked** or **Failed**). Under the title the row shows the project, before there is an outcome the round's state (**In progress** with a green dot, or **Judged**, without a check mark, for a judged round without a recorded quorum), the number of findings once judged, the number of reviewers, and when it started as a relative time ("just now", "5 min ago", "2 h ago", "3 d ago"; hover it for the stamp in UTC). The whole row is one link to the round's review, at least 44 px tall. The round id is below the link in small type; one click selects it for copying. `/reviews?project=<name>` chooses that project in the top bar's project filter (below); each project on the first page links there. Above the rounds, under "Pull requests that failed", a card for each watched pull request whose head failed last time it was tried names the pull request and whether it is backing off or was handed over to the maintainer agent ("Pull request 7: backing off"), shows the cause in red, then the failures in a row and the next try (UTC); the card goes once the head is read, its round is queued or its pull request is closed. The cause is redacted like a log line, so a configured key or token never appears on it. When a GitHub App installation is set (`GITHUB_APP_INSTALLATION_ID`), the section "Forge budget this hour" at the top lists it with its calls used and calls remaining this hour, from the latest answer GitHub sent, and marks the forge reserve **In force: routine reads wait** while less than the reserve is left (see [Intakt's GitHub App](README.md#intakts-github-app)), else **Not in force**; before an answer of this hour reported the budget it says "No reading this hour". The section shows what was known when the page loaded; reload to see newer figures.
- `/search?q=<words>` answers the search window of the top bar: not a page but a piece of one, a list of results in groups, in this order: **Actions**, **Reviews** (each round titled by its change and round number, such as "sample-change, round 2", with its project and state and, once it has an outcome, that outcome first in the row as the same icon-and-words chip the review page uses (Approved, Changes requested, Blocked or Failed), and, on a line below in small type, its round id, which one click on the id itself selects for copying; a round whose change has no name reads "Unnamed change", one without a number "round not numbered"; the whole row, at least 44 pixels tall at every width, links to its review, all but the id's own text; a round id typed into the search still finds its round), **Projects** (each with its number of review rounds, linking to its reviews) and **Pages** (Reviews, Projects, Trends and Components). Words are separated by any white space, including a no-break space or an em space, and spaces of that kind at the start or end of what you typed are ignored. A result is found when every word you typed appears in its name, its line under the name, its group's name or, for a review round, its round id, in any case; each group shows at most 10. Every result names its project, or says "All projects". With no words it shows **Recent**, the 5 newest review rounds, then the actions. When nothing matches it says "No results for" your words, suggests what to try (a project of yours by name, a round id or a page), and offers **Clear the search**, which asks again with no words. The only action today is "Switch light or dark theme".
- **Search**: the search window opens over the page, which stays behind a dark veil and cannot be reached until the window closes. The cursor is in its field, whose focus ring follows its rounded edge with room between the ring and the text, which starts empty and shows Recent and the actions; every letter you type asks `/search` again and shows its groups. The first result is highlighted: the Up and Down arrows move the highlight (past the last result it starts again at the top), Enter opens the highlighted result (a review, a project's reviews or a page) or runs it ("Switch light or dark theme" switches the look and closes the window), and Escape, Ctrl K (Cmd K) again or a click beside the window closes it and puts the cursor back where it was. A click on a result does the same as Enter, and pressing the mouse on a result leaves the cursor in the field, so the arrows and Enter keep working after it. The round id under a review is the exception: a click on the id itself selects it for copying and neither opens the review nor closes the window, while a click elsewhere on its line, such as on the words "Round id" or beside the id, opens the review like the rest of the row. Until the results for what you just typed have arrived, the arrows and Enter do nothing, so Enter never opens a result for other words. If you type with an input method that composes text, such as Japanese, Chinese or Korean input, Enter and the arrows go to it while it composes, so Enter confirms your text instead of opening a result. Tab stays inside the window. When nothing matches, **Clear the search** empties the field and shows Recent again. If Intakt does not answer, the window says "Search did not answer."; typing again asks again. On a phone (narrower than 761 pixels) the window fills the whole screen, shows a **Cancel** button next to the field instead of the key hints, and has result rows at least 52 pixels tall; Cancel closes it like Escape does, and Tab then also stops on Cancel. Matching words are not highlighted in the results yet.
- `/reviews/<round id>`, linked from each round on `/reviews`, shows the whole review the round belongs to: every round of the same change in the same project, in round order. A pull request's rounds count as one change whatever letter case names it (`acme/widgets` or `Acme/Widgets`), and also with a `#fragment`, a `?query` or a trailing `/` after its number, so they are numbered 1, 2, 3 in one sequence and shown as one review, also across an upgrade; rounds an older install stored under two spellings of one pull request (two letter cases, or an address with a `?query`, a `#fragment` or a trailing `/`) keep their own numbering and their own review. Such an old review kept apart is history only: its page offers no **Start round**, and new rounds of the pull request start from the review under its plain lowercase address. Two local branches whose names differ only in letter case (`feat/Widget` and `feat/widget`) are two changes, as git treats them, on SQLite and PostgreSQL; MySQL and MariaDB compare names without letter case, so there they share one numbering. Each round stored as a replay carries a **Replay** label beside its heading in the timeline, and beside "Now: round N" while it runs; a live round has none, also in a review that mixes live and replay rounds. Only when every round of the review was stored as a replay does a **Replay** label under the title say "A recording played back: its verdicts were never given on this change and never count as one." While the latest round is not judged yet and has not ended (see the end of this item), a current state block, "Now: round N in review", shows how many of its reviewers finished, each reviewer's role, model (its tier and `model not recorded` for a reviewer started before Intakt recorded the model or whose start recorded an empty model, as in the reviewer table, so the cell is never empty) and its outcome (or, while it has none, its state in muted words), the open findings (the act list of the newest judged round: every P1 and P2 finding that passed the quote check, whatever the judge marked, and the P3 findings the judge marked `act`, each linking to its card in the timeline below, which the page then shows just under the top bar (on a phone under the Timeline and Live log switch too), and each at least 44 pixels tall on a phone; "No finding is open." before any round is judged) and that the judge has not judged the round yet; on a page the live updates reach, the finished count changes as reviewers answer, a stopped reviewer turns `stopped`, and once the judge decides the heading shows the round's outcome with "Judged" in muted words, the open findings become that round's act list, and the block states the judge's call in the same words as the round's label ("Changes requested", for example, or "outcome not recorded" for a round started before Intakt recorded its quorum) and how many findings there are to fix as its first words ("Changes requested, 2 findings to fix."), then the link "See each finding in the round below." to the round ("See the round below." when none is left to fix), whose findings and calls the timeline then shows without a reload. The round's outcome line (the outcome and the quorum policy) also appears there without a reload. Under "Timeline", every round the judge has decided has a one-line heading (after the round number, its outcome as a label with its icon: "Approved", "Changes requested", "Blocked" or "Failed"; then "Judged" in muted text, `outcome not recorded` when the round has no recorded outcome, its number of findings, and the time it started and the time it was judged, in UTC) ending in a chevron that turns when the round is open; a click or Enter on the heading opens or closes the round, and Escape anywhere in an open round closes it and puts the keyboard back on its heading. The newest round of the review starts open when the judge has decided it, so a judged review shows its verdict and findings without a click; every other decided round starts folded to its line, also the newest judged one while a newer round is still in review; a round judged before Intakt kept the findings says `findings not recorded` there instead of a count, with how many ids the judge marked (`2 marked by the judge`) when it marked any; the round still running stays open. ### The Trends page

`/trends` (**Trends** in the menu, after Projects) shows how the reviews went, read from the ledger's review rounds of every project, whatever the project filter shows. When the install's [bench page](../bench.md#review-bench) (`docs/bench.md`) has its review bench table, the page opens with the bench result in words, such as "The review panel found 24 of 30 planted defects", then "N false alarms in all" (with the number of runs when the bench page states it once), a "measured" label and the date of the run; once a review has run, the octopus conducts beside it, or stands alone in that place when the bench page has no bench table (the only octopus on the page). Under it come tiles, three per row on a phone, each giving one figure above a short label with a few words saying what it counts, and a small role character in its corner (the meerkat for the passes and the findings only one reviewer raised, the owl for the tiles of the to-fix count, the time to verdict and the cost per pass); point at a label or reach it with the Tab key and a tooltip says more. A tile shows only when there is a figure for it, so a page with few reviews shows fewer tiles:

- **Passes** (caption "Reviews run so far"): every review round started.
- **To fix** ("Serious, kept by the judge"): the findings of severity P1 or P2 the judge put on a round's list of things to fix. A round with a finding on that list whose severity was not recorded (kept only as the judge's mark) is left out, because it may have been a P1.
- **One reviewer only** ("Findings no one else raised"): the share, as a whole percent, of the findings the judge kept to fix (one per entry on a round's list of things to fix) that only one reviewer of the round reported, over the rounds with a full record of who reported what. An entry counts with every finding the judge joined into it, so an entry that joins two findings of one reviewer still counts as one reviewer's, and two reviewers that reported the same known finding again both count. When a round completes, Intakt writes down which reviewer reported which finding; only rounds with that record for every reviewer that answered are counted (rounds completed before Intakt wrote it, or with a record that cannot be read, are left out), and the tile's tooltip says so. While no judged round has that record (or its rounds have no entry to fix), the tile is left out.
- **Time to verdict** ("Median, start to verdict"): the median over the judged rounds, from the round's start to the judge's call, such as `4 min 12 s`.
- **Cost per pass** ("Mean over priced passes"): the mean of the rounds that made a model call and whose cost is known, with the review page's "estimated" label; the label's tooltip names the price list's date.

Under the tiles, up to three charts, each with a short title and a chip saying whether its figures are counted or estimated, and, for a screen reader only, a table of the same numbers and a one-line takeaway; neither is shown on screen, and there is nothing to open. A chart with no data, or with only zeros, is left out, and so is one reviewer's small chart with only zeros:

- **Catches by reviewer:** one small chart per reviewer role (such as correctness and security), with a bar per severity (P1, P2, P3) counting the findings that role reported, all on one scale. A legend names the solid part of each bar, and the number in brackets above it ("3 (2 alone)"), as the findings only one reviewer reported (no other reviewer of the same round reported them); a finding the judge joined into an entry counts with the entry's other findings, and under the severity its own reviewer gave it, even when the entry took a higher one from a finding it joined. A finding dropped before the judge (it quotes code the change does not hold) still counts for its reviewer. The takeaway names the reviewer with the most P1 findings and how many of them only it found ("The security reviewer found the most P1 findings, 3, and 2 of them no other reviewer found."), names every reviewer tied at the top with how many only each of them found, or says "No reviewer found a P1 finding.". Each reviewer counts under the severity it gave, so two reviewers that report the same finding at different severities each count their own. Only judged rounds with a full record of who reported what, and at which severity, count, as for the "One reviewer only" tile; rounds from before Intakt wrote down those severities are left out.
- **Checked findings:** one bar per outcome over every judged round: **Kept to fix** (on the act list), **Merged** as a duplicate into another finding's entry, **Deferred** to a follow-up issue, **Rejected**. The takeaway reads like "The judge kept 9 of 14 findings and rejected 2.". Rounds judged before Intakt recorded the findings themselves (only the judge's marks are kept) are left out, because their rejected findings cannot be told apart, and so are rounds where the judge's answer could not be read (Intakt then puts every P1 and P2 on the act list and gives the P3 findings no call, so none of that is the judge's) and rounds from before Intakt wrote down whether that happened.
- **Passes and cost per day:** two small charts on one row of days, **Passes** and **Cost (USD)**, one bar per day on which a round started (days are counted in UTC; days with no round are not drawn). It shows only once rounds started on 3 or more days; before that it is left out, never an empty grid. The cost chart and the table's cost column appear only when at least one day has a cost; with none, the one chart is titled **Passes per day**. Rounds and cost are two charts, not two lines on one, so one color serves both. Each has its own takeaway ("Reviews ran on 4 days; the busiest was Oct 27, with 5 rounds.", "The costliest day was Oct 26, at about 0.0125 USD."), and the cost is marked estimated, as the cost tile is. A day's cost counts the rounds that made a call and is known only when every one of them has a price; a day without that reads "No data" (no bar, in the tooltip and in the table), never 0, and a positive cost reads "less than 0.0001" when it would round to 0.0000 at four decimals (0.00007, for example, reads 0.0001). A day with a positive cost always draws a bar, however small, so it never looks like a free day or a day with no data. Once the days span more than one year, each day carries its year. With many days, the numbers and day names under and above the bars show on every second, third or later bar so they do not overlap; the tooltips and the table still give every day. The screen-reader table lists each day with its rounds and estimated cost. With the **Demo review** toggle off, the demo's days are left out too, so the count of days can fall below 3.

Each bar can be reached with the Tab key, and pointing at it or focusing it shows a tooltip with the count first; it stays while the pointer is over a bar or a bar has focus, and Escape hides it, wherever the focus is. On a phone the charts stack.

A figure with nothing to read it from (no judged round, no judged round whose act-list severities are all recorded, no judged round that records who reported what, no priced round) has no tile, never a 0; a chart without data is left out. The recorded demo review fills the reviewer and judge charts on its own, so a played demo run shows them without a key; the per-day chart is then left out, since the replay is one day. A round counts in the reviewer and judge charts only when every finding the judge named is among the findings it recorded; the per-day chart counts every started round in the selected data. When the ledger holds rounds played back into the replay project (`intakt:demo:replay`), a **Demo review** toggle sits next to the title. It is on (pressed, with a check mark) while those rounds are counted; pressing it opens `/trends?demo=0`, which counts without them and shows the toggle off, and pressing it again counts them again. Before any review has run the page shows the waiting octopus and one button, **Start the first review**: on the compose demo it starts the sample review exactly as step 3 of `/setup` does; on an install without the sample change it opens that step of `/setup`, which says what is missing.

### Live updates (in progress)

While a review runs, Intakt sends each reviewer's tool calls, its text and each round's progress ("1 of 2 reviewers finished", "Judged"; sent when the round opens and on every change) to the live-update hub built into FrankenPHP. The round's state also counts how many reviewers started, from the same state as the finished count, and each update changes both together, so a page you opened before the reviewers started says "2 of 2 reviewers started" under Reviewers and "2 of 2 reviewers finished" in the current state block once the judge decides, without a reload. A reviewer's text before a tool call (what it says it reads next) is sent in one piece when it calls that tool. Its answer is never sent as the text it wrote. Once Intakt has read it, the review hands the live updates the verdict and each finding's severity, file and line and title (the first line of the finding's text; the live log shows it without its bold and italic marks and shortens what it shows to 160 characters ending in `…` when it is longer), or, when the answer could not be read as a verdict at all, only a note that it could not be read; the hub gets that and never the reviewer's raw answer, and the review page adds it to the reviewer's live text as a verdict line and one line per finding, or as the single note. The checks Intakt runs on a verdict it could read (a malformed tool call, a finding id reserved for failed reviews such as `reviewer-stopped`, an id that was not open, an id marked both resolved and repeated) come after that, so an answer they refuse still shows its verdict line and findings in the live log; the reviewer is then asked once more (the second try's text replaces it, as below) or, on a second refused answer, fails, and the refused verdict never counts. The review page of a round that is not judged yet and has not ended (blocked with no outcome in time, or because its judging failed) shows them without a reload: the round's "N of M reviewers finished" line and its "N of M reviewers started" line under Reviewers, each finished reviewer's outcome with its icon ("Approved", "Changes requested", "Blocked" or "Failed"; muted "answered" when its outcome could not be read, muted "stopped" for a stopped one) in the reviewer table as a reload shows it, with why a failed or blocked one ended (the finding count of a reviewer the table already listed appears after a reload) and in the current state block, the same count in the block (and "judged" in its heading once the judge decides, and the round's head turning from muted "In progress" to its outcome, or to muted "Judged" when it has no recorded outcome), the round's findings with the judge's call on each once the judge decides, and, in the live log beside the timeline, each started reviewer's tool calls and text. A reviewer that starts after you opened the page appears with its first tool call or text, under its role and model, and gets a row in the current state block named the same way (`running`, or its outcome once it finishes, or `stopped`); once it finishes or is stopped, it also gets a row in the reviewer table with its role, model, outcome and number of findings, as a reload shows it, without a stop button. When Intakt cannot read the reviewer's start from its ledger as it sends the update, the reviewer shows as "A reviewer (role not read)" in the live log and the current state block, and its table row says `role not read`, `model not read` and "shown after a reload", until you reload; such a row, and a reviewer the table already lists, then shows its state as a muted word ("answered", "failed", "blocked" or "stopped") instead of an outcome. The reviewer table of a round that is not judged yet and has not ended is shown also while no reviewer has started; an ended round without a started reviewer has no reviewer table. Every dashboard page (the project list, the review list, the review page and the Waiting on you page, whose items change only on the next load) also opens one live connection that listens to the shell topic `dashboard/shell`, and gets the same permission on every page, which covers the shell topic and every round's updates, so opening a list does not stop a review page in another tab from updating; only the project filter's list (when a project starts its first review round) and the board's headline line and its In review and Done columns (each time a reviewer starts and each time a round's progress changes) are published on it so far, and the board changes its headline line and those two columns to the pushed ones while the page is open, so a review that starts shows as a card in In review without a reload (a card you reached with the keyboard, or an explained term on it, keeps the keyboard focus when its column changes, and the page does not scroll); when the dashboard runs without live updates (for example without a hub key), the board shows the line and the columns as they were when the page loaded, and reloading the page shows the current one; the filter gains the new project and keeps the project this browser tab chose, so the lists do not change by themselves, and the review list and the project list show only what the ledger holds, also when the hub is down. The page needs a browser with JavaScript for this; without it, or when the hub is not running or `MERCURE_JWT_SECRET` is not set, the page shows the same state as the ledger on every reload and nothing else breaks. When the page loses its connection to the hub, a line at the top of the page says "Reconnecting." with the time it was lost, and counts down to the next try, every 5 seconds (Try now tries at once; a try still waiting for the hub's answer is left to finish); the top bar shows "Offline" (not on a phone). After two minutes the line turns red and says "Can't reach Intakt." Both go away once the connection is back, and if the page had received an update before the drop, the updates sent in the meantime follow. While the line shows, it adds that actions wait until the connection is back: the buttons that change something (Start round N, Stop, Stop this reviewer) are disabled, and enabled again once the connection is back; a button that was already disabled stays so. An elapsed time, such as "42 min", shows the time of the drop beside it ("42 min at 11:12") until then; no page but the components page shows one yet. To run the hub, set `MERCURE_JWT_SECRET` (at least 32 characters) in `.env.local` and start FrankenPHP from the repository with `frankenphp run --config Caddyfile --envfile .env.local --envfile .env`. FrankenPHP does not read the `.env` files on its own, and the first file that sets a value wins, so `.env.local` comes first. The same command also serves the dashboard in worker mode on port 7781 (`SERVER_PORT`), in the `dev` environment `.env` sets; because `.env` sets `DASHBOARD_PORT=7780`, its pages answer `400 Bad Request` there until `.env.local` sets `DASHBOARD_PORT=7781`. FrankenPHP's admin API answers on `localhost:2019` only, where `intakt:server:status` reads it. If the hub is not running, reviews are not affected: the update is dropped and a warning is logged. Intakt also has a general way to send updates to the other dashboard pages, which the project filter and the board's headline use (the Waiting on you count is planned to); it works the same way: when the hub is not running or refuses the update, the update is dropped, the warning "A live dashboard update was not published." is logged, and the page or work that sent it carries on. A `docker build` or an install from the repository needs `php bin/console importmap:install` once, to download Turbo for the dashboard pages that listen for live updates.

### The status document

Intakt can describe what it is doing as one JSON document, the status, which the owner's own dashboard reads until Intakt's dashboard replaces it. Its fields are documented in [status.schema.json](status.schema.json), a JSON Schema, and Intakt's tests check every document they build against that file. Print it with `php bin/console intakt:status --format=json` (JSON is also the format when `--format` is left out, and any other format is refused with an error): the command writes the document as one line and exits with 0. The dashboard serves the same document at `/status`, for example `http://localhost:7780/status` with the default `DASHBOARD_PORT`, as `application/json`; like every dashboard page it answers only when the address names `localhost`, `127.0.0.1` or `[::1]` with the dashboard's port, and answers `400 Bad Request` under any other name, so another site cannot read it through your browser. It answers `GET` (and `HEAD`, which returns the headers and no body); any other method is refused with `405`. The status is read from Intakt's database only, so it still answers while no worker runs; a stopped worker then shows as messages waiting in a queue.

- `generated_at`: when the status was read (UTC).
- `holds`: the install-wide holds in effect (`drain`, `failure-back-off`, `pause`, `budget-back-off`), the one that wins first. Only the name is given, never when it ends.
- `queues`: each background queue with the number of messages waiting for a worker (`async`, `failed`), or `null` for a queue that cannot count them.
- `projects`: one entry per project the watcher watches or the ledger names, by name. Each has:
  - `mark`: `replay` for a project stored as a replay (a recording played back for the demo, whose verdicts never count), else `live`. Each entry of `lanes.review`, `waiting_for_owner` and `last_outcomes` carries the `mark` of the round it names, as that round was stored: `lanes.review` and `waiting_for_owner` that of the latest round, `last_outcomes` that of the last ended round. A round started before its project was marked stays `live`, and a replay round started after a live round of the same change is `replay` while the live round's outcome stays `live`.
  - `lanes.review`: the review rounds in progress, newest first, each with its change, round id and number, start, its number of reviewers and one step per reviewer a worker has started (role, tier and `running`, `verdict`, `failed`, `blocked` or `stopped`). Fewer steps than reviewers means the others still wait for a worker.
  - `lanes.build`: each task `intakt:build:task` worked on, newest first, with the last step it recorded (`task`, `mirror`, `clone`, `build_job`, `hand_back_check`, `pre_push_check` or `push`), whether that step `passed` or `failed`, the failure's reason (or `null`) and when the step ended. A step recorded as `asked` is left out, so a task parked on a question shows its `clone` step as the last one, `passed`. A failed step is where the run stopped; a passed `push` means every step of the command passed. A task built again shows its latest run.
  - `guard_decisions`: the pull requests the watcher holds back: `pending` (CI still runs, with when it reads again), `red` (CI failed) or `failed` (the head could not be read, with the cause, the failures in a row and the next try).
  - `waiting_for_owner`: the changes on the board's Waiting on you column; empty for now, since Intakt places nothing there yet.
  - `needs_you`: the pull requests handed over after repeated failures, with the cause and the failures.
  - `last_outcomes`: the last ended round of each change, newest first by when it was judged or ended (a judging parked in the failure transport without a ledger record still counts as failed, with `end` `judging_failed`, and sorts by when its round started), at most ten. `end` says how it ended: `judged`, `judging_failed` (the judging failed for good, after the worker's retries; the dashboard shows such a round as **Failed**) or `no_outcome_in_time` (neither judged nor failed in its judging within its upper wait). A judged round has its outcome (`approve`, `changes`, `blocked`, or `null` for a round started before Intakt recorded its quorum policy) and when it was judged; a round that ended without the judge has `null` for both and is placed by when it ended (when its failed judging was recorded, or when its upper wait ran out). Such a round is no longer in `lanes.review`, and it stays the change's outcome while a next round of the change runs. A judging that failed for good is read from the ledger (event `judging_failed`), not from the `failed` queue, which no longer holds it.

The status carries no secret: a failure cause is redacted like a log line, so a configured key or a token in it shows as `[redacted]`, and holds and back-offs carry no end time.

### Checking the pages with the UI check

`bin/ui-check` opens the dashboard pages listed here in a headless browser, in the light and the dark theme, at 1440, 1920 and 390 pixels wide: `/` (the board), `/components`, `/projects`, `/reviews`, `/setup` (the first-run page), `/lanes` (the Status page), `/trends`, `/waiting` (Waiting on you), the search window open on `/reviews`, and the page of the first round `/reviews` lists. For each it reports the accessibility violations axe finds, counted by impact (critical, serious, moderate, minor) with the first elements each one names, and at 390 wide every visible text under 15 px (the text typed into a field, or its placeholder, too) and every button, link, field, search result or other control under 44 px tall (a control counts its label's height; a link inside a sentence is not counted). It saves a full-page screenshot of each as `var/ui-check/<page>-<theme>-<width>.png`, replacing those of the last run. It ends with exit code 0 when nothing serious or critical, no floor finding and no page error (a page that did not answer with success, a script error, or the wrong theme) was found, 1 otherwise, and 2 when it could not run (no browser, nothing answering at the address, or no review round to open).

It needs Node.js 22 or later, Playwright and axe-core, and a running dashboard with at least one review round:

```sh
npm install --global playwright axe-core
npx playwright install chromium
NODE_PATH="$(npm root --global)" bin/ui-check http://localhost:7780
```

The address defaults to `http://localhost:7780`. `CHROME_PATH` names a Chrome or Chromium to use in place of Playwright's own browser.
