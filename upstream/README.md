# Upstream reproductions

One folder per likely bug in a library Intakt uses (Symfony AI, the PHP MCP SDK, Symfony components, Doctrine): a minimal reproduction (PHPUnit tests, or a script named `reproduce.php`) and `REPORT.md` with the exact versions, what happens and what was expected.

Each `REPORT.md` ends with `## Upstream status`: the result at the pinned versions, the result on the upstream development branch (run in a scratch copy, never through Intakt's own `composer.json`), the upstream issues and pull requests found (or "none found", with the searches made), and the decision: `already reported`, `fixed upstream`, `ready to file` or `not a bug`. A later review by the owner adds an `Owner review` line with its corrections and a `Status` line with the next step; `not filed`, with the reason, marks a report that is not sent upstream although it was `ready to file`.

For a `symfony/ai` reproduction that is `ready to file`, the status also holds a `Fix pull request` line: `fix pull request ready`, or `issue only` with the reason. A fix pull request is right when the fix stays inside one package or bridge, the expected behavior is not in doubt, it breaks no backward compatibility, the package's own suite can test it, and no open upstream pull request already works on it (found by the files it changes, not only by title; merged pull requests since BETA1 count too). A prepared fix is built in a scratch clone of `symfony/ai` `main`, never in Intakt's dependencies, following that repository's `CONTRIBUTING.md` (`composer install` in the root and in the package, `./link`, the package's own `vendor/bin/phpunit` green), as one commit titled with its components (`[Store][Sqlite] ...`) and no `CHANGELOG.md` or `UPGRADE.md` change. The folder then holds `fix.patch` (`git format-patch`, applying to the `main` commit named in the status; its author is the builder identity, so the owner resets the commit author to their own before opening the pull request upstream, for example with `git am fix.patch` and then `git commit --amend --reset-author`) and `PR.md`, the pull request as it will be posted (template table, problem, change, tests, reproduction, `Out of scope`), with the patch's commit message under `Commit:` at the top. When an open pull request already fixes the bug, `COMMENT.md` replaces `PR.md`: a short comment for that pull request with the failing case and the test. `COMMENT.md` is also the text for an open upstream issue that already covers the bug or plans to replace the code, naming the issue on its first line.

A `ready to file` report with no fix pull request and no comment holds `ISSUE.md`: the upstream issue as it will be filed, with the repository, the template and the title on top, then the sections of that repository's bug report template (Symfony and Symfony AI use their bug report templates), the exact versions, a minimal reproduction inline, and the actual and expected behavior. For a Symfony or Doctrine bug it also says whether the fix looks small.

Nothing here is posted upstream without the owner's approval. Each new pre-release is run against these reproductions with `php bin/console intakt:upstream:run` to see what was fixed; a reproduction checks the expected behavior. PHPUnit tests assert it. A `reproduce.php` script (run from its folder, with the project's autoloader loaded) exits with 0 and prints `REPRODUCTION PASSES` as its last line only when the expected behavior held; anything else counts as `still fails`. A folder with `reproduce.php` is run as a script, never as PHPUnit tests. The gates skip this folder.
